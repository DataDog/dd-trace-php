# Playground

Bring up one of the `tests/Frameworks/*` fixtures in a container with the
locally-built tracer (+ optional appsec) loaded, so you can `curl` it to test
things manually.

Not for CI. The CI integration tests under `appsec/tests/integration/` use the
same `dd-appsec-php-ci` images and the same per-fixture `docker-init.sh`
scripts, so what you see here matches what CI runs.

## Prerequisites

- Docker with the `compose` plugin. The extensions are built **inside** a
  `datadog/dd-trace-ci:php-<ver>_bookworm-11` container (so Linux ELF .so
  files are produced regardless of host OS — no host-side build toolchain
  needed).
- On macOS/Windows, if you already have host-built `tmp/build_extension/`
  outputs from a previous local build, run `make clean-extensions` once
  before the first `make <Framework>` — the container can't load Mach-O or
  PE binaries. (Fresh clones don't need this.)

## Usage

```bash
make -C dockerfiles/playground Laravel8x       # bring up (defaults)
curl localhost:8080/
make -C dockerfiles/playground logs            # tail apache + ddtrace logs
make -C dockerfiles/playground shell           # bash in
make -C dockerfiles/playground down            # stop + remove container
```

## Env toggles

| Var | Default | Effect |
|---|---|---|
| `APPSEC` | `1` | `DD_APPSEC_ENABLED` — extension always loaded; this toggles runtime activation. |
| `TELEMETRY` | `0` | `DD_INSTRUMENTATION_TELEMETRY_ENABLED`. |
| `PHP` | per-framework | Override the pinned PHP version (must match a `dd-appsec-php-ci` tag). |
| `PORT` | `8080` | Host port forwarded to apache:80. |
| `DD_AGENT_HOST` | *(unset)* | If set, traces go to that host:`DD_TRACE_AGENT_PORT`. Otherwise dropped. |

Examples:

```bash
# Tracer-only (appsec extension loaded but disabled at runtime)
APPSEC=0 make -C dockerfiles/playground Laravel8x

# Point at a real agent on the host
DD_AGENT_HOST=host.docker.internal make -C dockerfiles/playground Laravel8x
```

## Framework targets

| Target | Fixture | Default PHP | Base image flavour |
|---|---|---|---|
| `Laravel8x` | `tests/Frameworks/Laravel/Version_8_x` | 8.1 | `apache2-mod-php` |

More to follow (Symfony/WordPress/Laminas variants).

## Caveats

- **Fixture is mounted read-write.** `docker-init.sh` writes to `.env`,
  `bootstrap/cache/`, Laravel storage, etc. After tearing down, `git status`
  on the fixture directory may show changes — `git clean -fd` and
  `git checkout .` on the fixture path to reset.
- **No agent by default.** Traces are generated by the tracer and dropped at
  the socket — fine for exercising extension/integration behaviour, but
  nothing appears in a backend unless you set `DD_AGENT_HOST`.
- **Only one playground up at a time.** Compose project is shared
  (`dd-playground`); running a second framework target replaces the first.

## How it works (short)

1. `make Laravel8x` depends on `_build-extensions` which builds
   `tmp/build_extension/modules/ddtrace.so` (via the repo-root `Makefile`'s
   `all` target) and `tmp/build_extension/appsec/ddappsec.so` (via cmake).
2. `docker compose up` pulls `datadog/dd-appsec-php-ci:apache2-mod-php-8.1-release`
   — the same image `appsec/tests/integration/.../Laravel8xTests` uses.
3. The repo root is mounted at `/project`; the appsec build dir at `/appsec`;
   the fixture at `/var/www`.
4. `entrypoint.sh` writes `/etc/php/php.ini` snippets to load both extensions,
   runs `/var/www/docker-init.sh` (which does `composer install`, SQLite
   setup, `php artisan migrate`, etc. for Laravel), then starts apache in the
   foreground and tails the logs.
