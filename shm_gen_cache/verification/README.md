# Production-code GenMC tests

These tests run the actual production Rust code of `shm_gen_cache` under the
GenMC model checker (RC11). Each test links the crate's real `src/` into a small
program with the harness (`src/lib.rs`, crate `genmc_harness`) and checks
universal safety properties and named reachable outcomes (witnesses).

This directory is the workspace package `shm_gen_cache_verification`: the
harness is its library, every test program is a binary (`src/bin/<name>.rs`)
and the runner is the integration test `tests/genmc.rs`, so rust-analyzer
covers all of it and `cargo nextest` runs it.

## Rules for this suite

* Prefer the public API. Internals are permitted when useful, through
  `shm_gen_cache::test_access` only.
* NEVER copy any part of a production file into a test to check its
  properties. Compile and link the production crate itself.
* If changing production code is unavoidable, isolate the change behind a
  named `cfg` or the `verify` feature (below) and explain its reason and
  semantic effect here.
* GenMC comes from a container image built from `~/repos/genmc`. Fix
  support for LLVM IR generated by rustc for this crate there (with a
  regression case under `tests/correct/infr/`) when avoiding the construct
  in GenMC builds is not reasonable, then publish a new image and update
  `DEFAULT_IMAGE` in `tests/genmc.rs`. Ask before implementing any other
  convenient GenMC feature.
* A successful safety check does not prove an outcome is reachable. Check
  existential outcomes separately with `witness!`, and accept only their
  specific assertions.

## Production-code variants

Bitcode builds compile the library with `--cfg 'feature="verify"' --cfg
sgc_genmc` and one wait variant: `--cfg sgc_genmc_short_waits`, or `--cfg
sgc_genmc_futex_model` for the programs listed in `FUTEX_MODEL` in
`tests/genmc.rs`. Native smoke builds are ordinary cargo
builds of this package, whose dependency on `shm_gen_cache` enables the features
`std` and `verify` only. The cfgs are declared in each package's `check-cfg`;
ordinary builds set none of them.

`verify` is a Cargo feature, not a cfg, because cargo cannot pass a cfg to
a dependency. It must never be enabled for production artifacts. Building
the library on its own (`cargo build -p shm_gen_cache`, as the bench and
the C build do) does not enable it; building the whole workspace
(`--workspace`, or a plain `cargo build` at the root) unifies features and
does, so never ship an artifact from such a build.

| cfg / feature | where | semantic effect |
|---|---|---|
| feature `verify` | lib | production assertions off, `test_access` public, `GetPid` test hooks called |
| `sgc_genmc` | lib | `fatal()` panics (a GenMC assertion failure after the runner's panic stubs); empty `cpu_relax()`; atomic zero fill in `Cache::initialize` |
| `sgc_genmc` | harness, tests | GenMC threads, `__VERIFIER_assert_fail`, real `assume` (else pthreads, abort, no-op `assume`) |
| `sgc_genmc_short_waits` | lib | rotation waits (`BoundedWait`) give up after 2 spin polls instead of the wall-clock budget; no clock, monitored sleep, futex or yield code |
| `sgc_genmc_futex_model` | lib (`FUTEX_MODEL` programs) | instead of `sgc_genmc_short_waits`: rotation waits block at once, without spin polls, in a model of the futex without a timeout |
| `genmc_witness`, `genmc_witness="N"` | harness, tests | only `witness!("N", ..)` is active; `spawn_symmetric` spawns plainly |
| `GetPid` hooks (not cfgs) | lib, per test | see below |

In detail:

* feature `verify`: verification build. `production_assert!` is compiled
  out (its condition is not evaluated); `test_access` is public; the
  `GetPid` test hooks are called (below).
* `sgc_genmc` (bitcode only, requires `verify`): `fatal()` panics instead of
  aborting, which the runner's panic stubs report as an assertion failure; `cpu_relax()` is
  empty, since inline assembly (`pause`/`isb`) cannot be interpreted (it has no
  shared-memory effect); the zero fills of `Cache::initialize` are relaxed
  atomic word stores instead of `write_bytes`, as GenMC's memset promotion does
  not cover every optimized aggregate initialization, and rustc has no flag that
  keeps it from emitting `memset` for them. The fills run before any thread
  exists, so they add no interleavings, and the memory ends up zeroed either
  way.
* `sgc_genmc_short_waits`: both rotation wait paths
  (`wait::BoundedWait` in `src/wait.rs`) give up after two spin polls
  instead of the native wall-clock budget of 5 ms. The clock reads, the
  monitored-line sleeps (inline assembly), the futex waits and wakes
  (system calls) and the scheduler yields are compiled out, as GenMC
  supports none of them; `wake_waiters()` after a release of rotation
  ownership is empty. The atomic polling, owner-liveness checks, slot
  reaping and final timeout branches are unchanged. The shorter limits
  preserve the kinds of interleaving under test without duplicating
  equivalent polling events. Native builds of the test programs keep the
  wall-clock budget, monitored sleeps, futex waits and actual scheduler
  calls.
* `sgc_genmc_futex_model` (instead of `sgc_genmc_short_waits`, for the
  programs in `FUTEX_MODEL`): the clock, monitored-sleep and yield code is
  compiled out as above, and so are the spin polls: waits block at once in
  `wait::futex_model` (a rotation's wait for a pin first flags the pin with
  `ROTATION_WAITING`, so that the unpin or the slot's reaping wakes it), a
  model of the futex made of atomics: a "kernel" lock makes
  checking the futex word and queueing atomic with respect to wakes; a
  wait whose word no longer holds the value the caller saw returns at
  once; otherwise it blocks until `wake_waiters()` on that word. The model
  has no timeout, so the wait never gives up. GenMC runs
  these programs with `-check-liveness`, which reports an execution in
  which the waiter blocks and is never woken (`Liveness violation!`).
  Natively such a lost wake only delays the waiter until its budget ends.
  For witnesses, `test_access::futex_model_woken_waits()` counts the waits
  that blocked and were woken, and
  `test_access::futex_model_unwoken_waiters()` the waiters blocked at the
  time of the call that no wake has reached yet (used to catch a waiter
  that blocked after the futex word went back to the value it saw, see
  `owner_wait_misses_reacquired_release`).
* The participant state needs no variant: it is always an `AtomicU64`
  decoded with shifts (bit 0 INITIALIZING, bits 1-31 PID, bits 32-63
  registration ID; 0 FREE), so no 32-bit field of a 64-bit word is ever
  loaded, which GenMC could not read.
* Test hooks: the `GetPid` methods `reservation_epoch_hook` (after W1 in
  `reserve()`), `reservation_retry_hook` (before abandoning a reservation
  attempt to rotate and retry), `after_epoch_publication` (in `rotate()`
  right after R5, before ownership is released) and
  `after_record_publication` (in `store()` after W6, before the unpin).
  They are called only under feature `verify`, default to empty inline
  functions, and only the liveness policy of the test that needs one
  overrides it; every other test and every ordinary build is unaffected.
  Their per-test semantics must be explained atop the test that uses them.

The lookup output buffer holds padded `u64` words and lookups copy cache
words into it directly; promotion keeps that padded representation. This
is the production API, not a checker variant.


## Run

Requirements: `cargo-nextest`, docker, and the GenMC image for the host's
architecture (pulled on first use). From anywhere in the repository:

```sh
cargo nextest run -p shm_gen_cache_verification        # the default suite
cargo nextest run -p shm_gen_cache_verification -E 'test(same_key_collision)'
cargo nextest run -p shm_gen_cache_verification \
  -E 'test(=concurrent_read_write::witness::V1)'
cargo nextest run -p shm_gen_cache_verification \
  -E 'not test(/::(safety|witness)/)'     # native and runner unit tests only
cargo nextest run -p shm_gen_cache_verification --run-ignored only
cargo nextest run -p shm_gen_cache_verification --no-capture  # see results
```

Trials, for every test program `src/bin/<name>.rs`:

* `<name>::native`: the program built natively by cargo (pthreads, failures
  abort), run once as a smoke check; it must exit 0.
* `<name>::safety`: GenMC must explore every execution without a violation.
* `<name>::witness::<NAME>`, for every `witness!("NAME", ..)` in the
  program: GenMC must report exactly that witness as reachable.

The binary `classify` holds unit tests of the runner's result
classification and panic stubs (`tests/genmc/classify.rs`).

The GenMC trials of `lookup_during_reuse` are ignored by default
(`GENMC_IGNORED` in `tests/genmc.rs`): its safety check explores about 1.5
million executions, minutes even with many GenMC threads. Run them with
`--run-ignored only` (just the ignored trials) or `--run-ignored all`. Its
native trial always runs.

Environment overrides:

| variable | default | meaning |
|---|---|---|
| `SGC_GENMC_IMAGE` | `SGC_GENMC_REPOSITORY@`, then the digest pinned in `tests/genmc.rs` | GenMC container image |
| `SGC_GENMC_REPOSITORY` | `ghcr.io/cataphract/genmc` | repository of the pinned image (CI uses the internal mirror) |
| `SGC_GENMC_DOCKER` | `docker` | docker-compatible CLI |
| `SGC_GENMC_NTHREADS` | a quarter of the cores | GenMC `-nthreads` |
| `SGC_GENMC_ARGS` | (none) | extra GenMC arguments, whitespace-separated (e.g. `-disable-spin-assume`) |
| `SGC_GENMC_TIMEOUT` | 3600 | seconds per tool invocation; the runner then kills the container |

`.config/nextest.toml` (at the repository root) runs at most four GenMC
trials at a time (test group `genmc`) and gives them a long slow-timeout;
native and unit trials are unrestricted.

The image is multi-arch (`linux/amd64` and `linux/arm64`); docker picks
the platform of the host, so no emulation is involved. The GenMC trials are
never skipped: an unavailable docker or image fails every GenMC trial,
naming the command and its log.

rustc runs in the repository, so `rust-toolchain.toml` selects the pinned
toolchain; it compiles for the Linux target of the host's architecture
(`x86_64-unknown-linux-gnu` or `aarch64-unknown-linux-gnu`, which must be
installed with `rustup target add`), as GenMC runs in a Linux container of
that architecture. The trials fail unless rustc's LLVM major version equals
that of the image's LLVM (`/usr/lib/llvm-21/bin`, whose `llvm-link` and
`opt` they also use).

Artifacts live in `target/tmp/genmc-verification` (cargo's
`CARGO_TARGET_TMPDIR`), which is mounted into the container at the same
path:

* `trials/<name>.<variant>/`: the latest run of one trial: every log, the
  intermediate bitcode and IR (`program.ll` is what GenMC checks) and
  `commands.txt` (exact command lines). A failure names the log to read.
* `cache/`: the library and harness builds and the toolchain check, shared
  by every trial. Each entry is keyed by a hash of the rustc version, the
  flags and cfgs, the target, and the sources (or of the image), built once
  under a file lock and valid only once its `.done` marker exists, so
  concurrent trials and later runs reuse it. Delete the directory to start
  afresh.

Timeouts, missing tools, compilation failures, checker crashes, zero
completed safety executions, unrelated counterexamples and a witness that is
not reported all fail the trial.

## Pipeline

For each test and variant (safety, or one witness):

1. The library is compiled as an rlib plus LLVM bitcode, with the variant
   cfgs above and the program's wait variant (once per variant, cached).
2. The harness (crate `genmc_harness`) is compiled with `--cfg sgc_genmc`,
   plus `--cfg genmc_witness --cfg genmc_witness="NAME"` for a witness
   variant (cached per cfg set: `Scope::spawn_symmetric` depends on it),
   and the test with the same cfgs.
3. `llvm-link` joins test, harness and library bitcode, so that no library
   function stays an undefined external.
4. `opt -passes=internalize,globaldce` keeps only what `main` reaches. This
   drops, e.g., the runtime configuration validator, whose intrinsics
   (`llvm.fptoui.sat`, ...) GenMC cannot lower, but which a static
   configuration never calls.
5. Declarations of precompiled `core` panic entry points
   (`core::panicking::*`, slice index failures, ...) get bodies that call
   `__VERIFIER_assert_fail` with the function's name, so a reached panic is
   an ordinary counterexample instead of "unknown external function". This
   rewrite runs on the host; steps 3, 4 and 6 run in the container.
6. `genmc -rc11 -disable-mm-detector -disable-estimation
   -disable-code-condenser -mode=verify -nthreads=N program.ll`, plus
   `-check-liveness` for the programs in `FUTEX_MODEL`. No loop, context
   or execution bound; GenMC's spin-loop reduction stays on. The trial
   prints GenMC's complete and blocked execution counts.

Compiler flags (`BITCODE_FLAGS` in `tests/genmc.rs`): `-Copt-level=3 -g
-Ccodegen-units=1`, `-Cpanic=abort`, debug assertions and overflow checks off
(the release profile; at opt-level 0 the IR is full of checks and
variable-length copies GenMC cannot handle), `-Cno-vectorize-loops
-Cno-vectorize-slp`, `-Cllvm-args=-inline-threshold=10000` (exposes local
copies to scalar replacement) and `-Cllvm-args=-unswitch-threshold=0`
(unswitching on properties of a constant key leaves freezes of constant
aggregates that GenMC cannot evaluate; it preserves semantics either way).

Classification (`classify()` in `tests/genmc/classify.rs`, unit-tested by
`tests/classify.rs`): the log must contain `*** Transformation complete.`
and no `INTERNAL FAILURE`, `LLVM ERROR` or line starting with `ERROR:`.
Safety: exit 0, `No errors were detected.` and more than zero complete
executions. Witness: exit 42 and every reported error is a `Safety
violation!` whose `Assertion violation:` message is exactly
`GENMC_WITNESS_<NAME>` (several workers may report; their reports can run
together on one line). Assertion locations are those of the harness, not
the test line, so the message, not the source line, identifies the
witness.

## Writing a test

A test is `src/bin/<name>.rs` plus the line `{ name = "<name>", test =
false, bench = false },` in the `bin` array atop `Cargo.toml` (the build
fails without it, naming the program). `test = false` is needed because a
program defines the C `main` itself (`#![no_main]`): a libtest build of it,
which cargo and nextest would otherwise make and list, runs the program
instead. The trials need nothing else: the build script lists the
programs, and the runner reads each source for its `witness!("NAME", ..)`
invocations (written literally, with a name in `[A-Za-z0-9_]` that is
unique in the file; anything else fails the `<name>::witness::discovery`
trial rather than dropping a witness). Keep configurations small, and
describe the setup, the properties, every `assume` and the limits in the
file's opening comment. Skeleton:

```rust
#![no_std]
#![no_main]

use genmc_harness::{Lent, check, check_ok, scope, witness};
use shm_gen_cache::{Cache, CacheStorage, NoopGetPid, ParticipantLock,
                    StaticParams, static_config};

static_config! {
    struct Cfg: NoopGetPid { participant_capacity: 2, bucket_count: 8, /* ... */ }
}

struct Insert<'a> { participant: Lent<'a, ParticipantLock<'static, Cfg>>, ok: bool }

fn insert(op: &mut Insert) { op.ok = op.participant.insert(1, b"k", b"v").is_ok(); }

#[unsafe(no_mangle)]
extern "C" fn main() -> i32 {
    static STORAGE: <Cfg as StaticParams>::Storage = CacheStorage::new();
    let cache = check_ok!(unsafe { Cache::initialize(STORAGE.as_mut_ptr(), STORAGE.len(), Cfg) });
    let mut p1 = check_ok!(cache.register_participant());
    let mut op = Insert { participant: Lent::new(&mut p1), ok: false };
    scope(|s| s.spawn(insert, &mut op).join());
    check!(op.ok);
    witness!("INSERTED", op.ok);
    0
}
```

Shared test helpers outside the harness live in
`shm_gen_cache::test_access` (`src/test_access.rs`), because they need crate
internals: besides the raw words (`global_epoch`, `rotation_owner_word`,
`arena_ctl_word`, `state_word`, `pinned_epoch`, `chunk`, ...)
it has decoders that perform exactly the loads they name and no more:

* `arena_state(cache, i, order)`: control word plus occupancy counter (two
  loads); `arena_ctl(cache, i, order)`: the control word only (one load).
  Use the latter for in-race observations, where an extra occupancy load
  would be an extra racing read that enlarges the explored executions.
* `registration_id(slot)`: one relaxed load of the state word, decoded,
  without the production assertions (which would also call the liveness
  backend).
* `record_header`, `record_lengths`, `record_word(cache, arena, offset,
  order)`: one load of a record-area word, decoded.
* `distinct_bucket_hashes::<N>(bucket_count)`: `N` hashes with pairwise
  distinct home buckets (const fn).
* `rotate`, `acquire_rotation`, `probe`: the real internal operations, for
  staging states.
* `stage_interrupted_reap(cache, slot, pid, start, crash)`: the state a slot
  reaper leaves when it dies at `crash` (a `ReapCrash`) in its steal of a
  dead claim, which no thread can be stopped at.

Harness API (`src/lib.rs`, documented there):

* `check!(cond)` / `check!(cond, "why")`: universal property; the failure
  message carries file, line and condition.
* `check_ok!(expr)`: checks `Ok`/`Some` and yields the value (no
  `unwrap()`: its formatting machinery must not be reachable).
* `witness!("NAME", outcome)`: `outcome` must be reachable. Active only in
  the `NAME` variant. Put witnesses after every check.
* `scope(|s| ..)` with `s.spawn(f, &mut arg)` / `s.spawn_symmetric(f, &mut arg,
  &predecessor)`: threads running a function item or non-capturing closure on an
  argument borrowed from outside the scope (like `std::thread::scope`).
  `Thread::join()` joins one (also from another thread of the scope); the end of
  the scope joins the rest, so a leaked `Thread` cannot outlive its argument
  (`unsafe Thread::leak()` opts out, for a thread parked forever). Symmetry is
  used only in the safety variant (a witness must distinguish the symmetric
  threads), and the types ensure that the predecessor runs the same function.
* `assume(cond)`: prunes executions (a no-op natively).
* `abandon_thread()`: stops the calling thread without unwinding (a crashed
  participant); parks natively.
* `current_thread()` / `Thread::id()`: comparable thread identities.
* `Lent::new(&mut lock)`: hands a participant registration (`!Send`) to one
  worker for its lifetime.
* `padded_words::<W>(bytes)`, `words_eq(a, b)`: expected output-buffer
  words, and their comparison.

IR constructs to avoid in test code (observed under GenMC):

* `==` on arrays or slices of words (`[u64; 2] == [u64; 2]`): rustc emits
  one wide integer load, a mixed-size access GenMC rejects. Use
  `words_eq`, or compare single words.
* Byte loads of words written by a lookup (comparing byte slices of the
  output buffer): a mixed-size access. Compare words with
  `words_eq`/`padded_words`.
* Variable-length `copy_from_slice` or slice comparisons in checked code:
  a runtime-length `memcpy`/`memcmp` that GenMC cannot always promote.
* `unwrap()`/`expect()`, `assert!`, formatting: reach `core::fmt`. Use
  `check_ok!` and `check!`.
* `core::hint::spin_loop()`, `std` (threads, TLS, I/O), system calls.
* Small structs of atomics on `main`'s stack that rustc initialises with
  one `memset` (seen with seven `AtomicBool` flags): later loads of the
  stack location read an initial value GenMC did not record as a store,
  and GenMC stops with the internal failure `!(haveNAs_ &&
  access.addr.isDynamic() && !pruned_)` (`ExecutionGraph.cpp`). Keep
  coordination flags in const-initialised `static`s.

Liveness/identity fixtures are `GetPid` implementations defined by the
test (static methods, so they need statics for state); see `src/pid.rs`.
Recovery tests may stage abandoned registrations; describe what the staged
state proves in the test's opening comment.

"Diverges": the test itself waits in unbounded polling loops (flags, owner
word), which only spin-assume makes finite. So does the futex model of the
`FUTEX_MODEL` programs (the last six rows): its lock and its blocked
waiters poll.

In the first four rows, spin-assume prunes executions: GenMC recognises the
retry after a failed index CAS in `table_put` (an iteration whose only
effects are loads) as a spin loop and blocks the redundant iterations. An
execution in which the CAS fails and the next iteration's acquire load
reads the winner is equivalent to one in which the first load reads it.
