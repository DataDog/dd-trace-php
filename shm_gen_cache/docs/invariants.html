shm_gen_cache: algorithm invariants and proofs

This document states and proves the concurrency invariants of shm_gen_cache, the lock-free shared-memory generational cache of dd-trace-php, at shared layout version 12 (LAYOUT_VERSION, lib.rs:89).

Two artefacts back the claims made here:

  • This document: pen-and-paper proofs against the source.
  • verification: GenMC model-checks the production code itself, under RC11, on small configurations (section 15).

A Lean 4 model of these events, in lean_model, machine-checks most of the proofs.

File and line references (store.rs:264) are to shm_gen_cache/src/ and link to it at commit ffc28f4fff.

Guarantees

  • G1, hit integrity and provenance. A lookup hit returns exactly the value one store attempt wrote for that key, never a torn, mixed or recycled value. Every published key/value pair was passed together to some insert(). (HT2, HT3.)
  • G2, memory safety. Every shared load and store addresses a word inside the mapping, whatever earlier loads returned. (BD1, BD2, SP4.)
  • G3, no write into a reused incarnation; serial rotation. An arena is reset for its next incarnation only after every store attempt of the previous one has finished, or has been reaped. Rotations behave as if they ran one at a time, and the epoch climbs by one per publication. (QU1, QU2, OW2, EP1-EP4.)
  • G4, promotions cannot resurrect a superseded insert. Let insert I of key k return Ok after publishing in epoch φ. A lookup of k whose final pass's V1 happens after that return may miss. Any hit originates in I or a same-key insert later than or concurrent with I, never one that precedes I (its return happens before I's call), regardless of promotions or rotations (FR3). The supporting property is that a promotion copies the last publication of its key in the source generation (FR2). If, besides, the lookup's final pass reads epoch φ or φ+1 and reads no store of incarnation φ+3 or later, it does not miss: it returns a hit, InsufficientCapacity or Corrupt, never Ok(None) (FR4). (RD1, RD2, FR1-FR4.)
  • G5, failed inserts are invisible. An insert() that returns an error other than Corrupt makes no I2: no index entry is a publication of any of its records. So no lookup ever returns a record written by a store attempt that descends from it, directly or as a promoted copy, in any generation. Corrupt returns are outside this guarantee. Limits: a failed insert can still have side effects: the rotations it performs or triggers, which evict the oldest generation, so an older value of the key may stop being returned; slot reaping; and record-area space consumed by bytes reserved, or written but never indexed. So a lookup after a failed insert is not guaranteed to return the previous value, only not to return the failed insert's. (FR5.)

Non-goals:

  • Recency beyond G4. G4 orders by happens-before, not by real time. A lookup that does not happen after an insert may still return an older value, but its promotions cannot make a later lookup covered by G4 return a superseded insert's record. Inserts of one key that are not ordered by happens-before are not ordered against each other, and one that lands in a later generation can win. A failed insert is invisible (G5) but not undone: its rotations may evict the key's older value, so a lookup after it need not return the previous value. A lookup whose retries take it to epoch φ+2 or later may miss the key (FR4).
  • Liveness. Wake-ups, wait budgets and timeouts are not treated. RB5 is the only liveness-flavoured property stated. Nor is the promotion sampler: no fairness, and no eventual promotion, is assumed. Section 16 lists the known holes.

2. Model and notation

The proofs use the C++20 memory model that Rust atomics adopt ([intro.races], [atomics.order], [atomics.fences]). Read in RC11 terms, each argument is the acyclicity of hb or of psc. GenMC checks the code under RC11.

Threads are written θ, fences f, a particular O3 event o3, and the epoch in which a returning insert published φ (G4, FR3, FR4). F1-F15 always denote code facts, never fences. S is the single total order of SeqCst operations; to avoid a clash, the scan load is written Sc and the liveness verdict vd. Like Z(e) for the seal of e, Cert(n) denotes any readiness certificate for n (section 4.2).

The remaining rule of [atomics.fences] (a release fence sw an acquire load that reads a write sb-after it) is not used by any proof here.

A0 (memory model). Executions are RC11-consistent, with hb the transitive closure of sb, sw and asw. mo is well-founded (has no infinite descending chain), and every read reads exactly one write. SeqCst fences are ordered by an acyclic psc. The proofs use only the C++20 release sequence, continued by RMWs only. That definition is contained in C++11's, so the proofs hold under both. With the A3 edge in hb, the model is RC11 plus asw, not pure RC11: without it, the steal cases of SL1 and OW1 would have no hb edge.

A set of actions is serial when hb totally orders it.

Serial-reads lemma. On a serial set of writes to one word, mo agrees with hb (COH-WW). A load that is hb-ordered against every write to the word reads exactly the latest write that happens before it (COH-WR, COH-RW).

Chains such as O4 sb P3 sw P1 read left to right and compose into hb.

3. The algorithm

3.1 Overview

The mapping holds a header, one cache-line slot per participant, and three arenas. Each arena has a control word ctl, a readiness word (the last epoch certified as a promotion source), an occupancy counter (exact mode only), an index of stamp:32, ref:32 entries and a record area. Incarnation e lives in arena emod3; while the global epoch is e, lookups probe incarnations e and e−1, inserts write into e, and the third arena waits to be reused as e+1.

Registration. A thread claims a FREE slot (P1, P2) with a fresh registration id, and releases it at the end (P3). When every slot is taken, it may steal the slot of a dead participant (P0-P6). The steal asks the liveness backend for a verdict about the claim it replaces.

Insert. A pass of reserve() loads the epoch (W1), pins it (W2), fences (W3) and prechecks the arena (B0). It then cuts the record from its private chunk (H1), or reserves with a fetch_add on the bump (B1), possibly claiming a new chunk (H2). The insert then stores the payload and the header (W4, W5), publishes the index entry (I0, I2), updates the occupancy (W6) and unpins (W7). A pass that finds the arena sealed or full unpins and rotates instead.

Rotation. The rotator takes ownership of the rotation-owner word (O1, O2), rechecks the epoch (R0) and seals the current arena (R1). Right after the seal loop it runs a SeqCst fence (R1F). It then scans every pin (R3), waiting for, or reaping, pinners of an epoch at least two old (R3A, reap_pinner). The same scan notes whether any slot is pinned to the epoch e it has just sealed; pins of e never block and are never reaped. If it saw none, it certifies e as a promotion source (R3C). It then resets the arena to be reused (R4), publishes the next epoch (R5) and releases ownership (O4).

Takeover. A rotator that finds a dead owner examines the owner's slot (reap_owner()) and, unless the owner is live, takes ownership over with a CAS (O3).

Lookup. A lookup loads the epoch (V1) and probes e, then e−1. It loads index entries (I1), fences (I1F), loads the record (D4, D5), fences again (D6) and reloads the epoch (V2), returning Retry when the probed incarnation is two or more epochs old. Before probing e−1 it loads that arena's readiness word (C0). Probes do not pin and write nothing, except a recheck's certificate (C4, a fetch_max made unpinned); a promotion pins and writes through store().

Promotion. Copying a hit from e−1 into e is hazardous while a writer of e−1 is still in flight: an insert of v2 pinned to e−1 may publish after a lookup has already read the older v1 there and return, and the promotion would then republish v1 in e, shadowing the completed insert for every later lookup (section 16, item 2). A certificate for n says that every store attempt for n has finished, and makes their writes visible to whoever reads the certificate (RD1, RD2). A probe ordered after it therefore reads the key's last publication in n (FR1, FR2). The order matters: a certificate learned after the probe's loads does not order them, hence C0 precedes the first I1, and a certificate obtained later leads to a fresh probe. The mechanism: a hit in e−1 after a miss in e is stored again, into e only (only_epoch), through the same insert path, but only if e−1 is certified: either C0 read the certificate for e−1 before the probe read anything, or a sampled recheck (C1-C4) certifies it now and a fresh probe of e−1 (the reprobe) supplies the copy that is promoted. Otherwise the hit is returned unpromoted. The recheck neither waits nor reaps. The sampler rechecks with probability min(1, 8 / bucket_count), drawn from a per-registration SplitMix64 stream. A promotion is also dropped if the epoch moved on or the arena has no room, and when no index slot accepts it, without rotating. Once published, it triggers the same maintenance as an insert: a rotation at the occupancy target. The C API's lookup documentation (ffi.rs:496-504, and the generated shm_gen_cache.h) states the same contract, including that the reprobe's result, possibly a miss or InsufficientCapacity, replaces the hit.

3.2 Terms

Event labels are those of section 3.1; section 4.2 tabulates them.

  • A claim c of a slot is a successful P1 or P4; the registration it starts lasts from that CAS until its P3, a P4 stealing it, or the end of the execution. The registrant of a slot is the thread holding its current registration. Actions on behalf of c are those its thread makes for it from the claim to its P3 (A2). A rotator that steals a slot in reap_pinner() briefly holds a second registration: its events from that P4 to the P3 that releases it (T2, P5, P6, H0) are on behalf of the second registration, not of the rotator's own c; being made by the rotator's thread between c's claim and P3, they are also sb-ordered with c's actions. The register of c is its P2 or P5. The ender of c is the state write that ends it: its own P3, or a P4 stealing it.
  • A tenure t is one hold of rotation ownership, from its acquiring CAS At (a successful O2 or O3) until its O4 or the holder's death. Actions under t are those its holder makes from At to its O4. R0(t) is the value its R0 read. A publishing tenure is one that executes R5.
  • Incarnation e is arena emod3 while it serves epoch e. The base of incarnation e is a ctl write that starts it: an R4 stamping e, or the initial value for e=2.
  • A pass is one iteration of reserve()'s loop, from W1 to the return of a reservation or to W7. A store attempt w is a pass whose B0 saw (stampew,unsealed), extended through its record stores, I2 and W6 to its W7 (store.rs:175, or store.rs:352 for an attempt that stops). Its actions from W2 to W7 are the events of the pass from W2 on, and of the store that follows it, up to that W7 (or to the end, if the thread dies). An attempt may stop at the target check or fail at B1; if it succeeds, it writes and publishes one record.
  • A chunk is the unused tail [cursor,end) of a B1 claim larger than its record, kept in the slot's chunk words for later cuts in the same epoch.
  • An announce is the scan's R3A, a CAS that sets the ROTATION_WAITING flag in a pin it waits on. The head of a pin write w is the last non-announce write at or before w in mo(pin) (or init): w lies in its release sequence (PN1).
  • An insert operation I is one call of insert(), from its call to its return; its store attempts lie in between (F15). Insert J precedes insert I when J's return happens before I's call. A store attempt descends from insert J if it is an attempt of J, or a promotion attempt whose promoted hit's I1 read an entry published by an attempt that descends from J. Each attempt descends from exactly one insert, its root. By induction on the attempt's epoch: an insert attempt belongs to one insert, and a promotion attempt to none (F15); a promotion attempt copies one hit (F10), whose I1 reads one entry, whose publication belongs to one attempt (F2) of the epoch before.
  • A certificate for n is a release fetch_max with argument n on the readiness word of arena nmod3: the R3C of a tenure with R0 =n, or the C4 of a recheck whose C1 read n+1 (Cert(n)).

4.3 Label conventions

  • One letter per operation family, numbered in program order: W (insert), B (reservation), H (chunk), I (index), D (record loads), V (lookup epoch), O (ownership), R (rotation), P (slot state), T (start time), C (promotion certificate: a probe's readiness load and the recheck). Two exceptions. The D family starts at D4: D4-D6 are the labels of the source comments, and there are no D1-D3. The I family spans two operations: I0 and I2 belong to table_put() (insert), I1 and I1F to probe() (lookup), so its numbers are not one program order.
  • 0 marks an access before the family's numbered sequence: the load that an RMW or a decision is predicated on (B0, I0, O0, P0, T0, R0; C0, on which the decision to promote is predicated), or the chunk reset (H0).
  • A letter suffix marks an auxiliary access attached to a numbered event: I1F (the fence after I1), R3A (the announce inside R3), R1F (the fence after the seal loop of R1), R3C (the certificate earned by the scan R3).
  • Z(e) is notation, not a label; so are vd, init, reap_owner() and reap_pinner(); so are Cert(n) and reprobe_for_promotion().

7. Informal proof outline

This section tells the whole story without citing rules; sections 8-13 make each step precise. There, each invariant has an Outline before its Proof; where the proof is itself one or two sentences, the two are merged as Outline and proof.

Slots behave sequentially. A slot's state word changes only by compare-and-swap, so its history is a chain: a claim, its register, then the write that ends it, and the next claim. A normal hand-over goes through a release (P3) that the next claim (P1) acquires. A steal goes through the liveness verdict: a "dead" answer orders everything the dead thread did before it, and the steal's CAS confirms that the verdict was about the claim being replaced. So everything one registration does happens before the next registration of the slot starts. Its pin and its chunk words then behave like private variables passed down a chain of owners.

Ownership is a lock, takeovers included. The rotation-owner word works as a lock: O4 releases, O2 acquires. A takeover O3 does not read the owner's release. Instead the taker learns from the owner's slot, with acquire loads, that the owner's registration is over: either it stole that registration itself after a dead verdict, or it saw a later state of the slot, which carries the release of whatever ended the owner. Either way, everything the old owner did happens before the takeover. So rotations run one after another, each starting from the epoch its predecessor published: the epoch climbs 2, 3, 4, ... and every rotation seals its arena before publishing.

Writers are seen by the rotation that reuses their arena. A writer pins its epoch, fences, and only then checks that its incarnation is unsealed. The rotation that will reuse that arena, two epochs later, fences right after its own sealing step, under ownership, and that fence comes after the seal of the writer's incarnation through the chain of ownership handoffs. Two SeqCst fences on opposite sides of the seal cannot both miss each other: either the writer saw the seal, and stops, or the rotation's scan sees the pin. The rotation then waits until the pin moves on (an unpin, a new pin, or a reaper's clear). Each of those is a release made after the writer's last write, so the reset of the arena happens after everything the writer did there. Incarnations of an arena are therefore serial, and a pinned writer never sees a later incarnation.

Within an incarnation, space is handed out once. The bump is a fetch_add that lands inside its incarnation, so successful reservations are disjoint intervals. A slot fails at most one add per incarnation, so the bump stays below 2^31. Chunks are private to their registration and are reset on every claim, so cuts are disjoint too. Each attempt writes each word of its own reservation once.

A reader that follows a publication reads that record. The index publication is a release after the record stores, and the reader fences with acquire after loading the entry. Every record word it then loads holds that attempt's store, unless the arena was reused meanwhile. In that case the reader read a store made after some writer's SeqCst fence, its acquire fence D6 synchronises with that fence, and the epoch reload V2 sees the newer epoch and makes the lookup retry. The 32-bit stamps do not alias because no entry or lookup lives for 2^32 epochs.

Every published pair comes from an insert. An insert stores the pair its caller passed. A promotion stores its caller's key and the value of a validated hit in epoch e−1, which, by the previous paragraph, is exactly the pair some earlier attempt of e−1 wrote for that key. That attempt is an insert or, again, a promotion from an even older epoch, so an induction on the epoch traces every pair back to an insert().

A promotion copies a finished generation. The rotation that seals e fences right after sealing and then sees every writer still pinned to e: a writer whose fence came first in the SeqCst order is in the scan, and one whose fence came later sees the seal and writes nothing. If no slot is pinned to e, every writer of e has unpinned, each unpin is a release made after all its writes, and the scan acquires it; the rotation then publishes a certificate for e with a release. A lookup acquires that certificate before reading anything in e, or rechecks the pins itself and then reads e again. Either way every write of e happens before the reads that supply the promoted copy, so each index load sees the last entry of its slot, and the promotion copies the key's last publication in e. A copy read before the certificate was learned may be stale; it is returned but never promoted.

Promotions cannot resurrect a superseded insert. Suppose insert(k, v) returned Ok after publishing in epoch φ, and a lookup's final pass starts happens-after that return. It reads an epoch g≥φ. In incarnation φ, any probe reads the insert's entry in the key's slot, or a later entry for k from an insert that did not come before. Later incarnations hold only inserts that did not come before, and promotions, which copy the last value of the generation before theirs. If g=φ and the lookup falls back to φ−1, its probe of φ missed although the key's chain in φ happened before it; that requires reading a store of incarnation φ+3 or later, and the validation of whatever the lookup then hits forces a retry. So the lookup never returns a value whose origin is an insert that came before, regardless of promotions or rotations. It may miss; no retention is assumed. If, besides, its final pass reads φ or φ+1 and nothing of incarnation φ+3 or later, it does not miss: it hits, or fails with InsufficientCapacity or Corrupt.

A failed insert leaves nothing to find. An insert that returns an error other than Corrupt publishes nothing: its input was too large, its reservation or rotation failed, or its record found no bucket and the rotation that should make room failed. Corrupt returns are outside this guarantee. A promotion copies a hit, and a hit is always a publication, so nothing copied from the failed insert can exist either. Its side effects remain: its rotations may evict the key's older value.

Bounds checks hold whatever was read. Every index value, however stale, encodes an offset inside the record area. The readers bound the header's length against the area before loading anything else, and derive every further address from values that passed those checks.

8. Proofs: slots and ownership

SL1. Slot serialisation

Statement. For one slot:

  • (a) After init (FREE), mo(state) is a sequence of claim blocks. Each claim c (a P1 or P4) is followed by at most its register (P2 or P5), then by at most one write ending c: its own P3, or a P4 stealing c. A P4 may follow INITIALIZING(c) directly.
  • (b) If claim c precedes claim c′ in mo(state), every action on behalf of c happens before the claiming CAS of c′, and hence before every action of c′.
  • (c) Every state write mo-after c's register is the write that ended c or comes after it.

Outline. All writes after init are RMWs, so mo(state) is a chain in which each write reads its predecessor; unique claim words (A4) leave room for only the shape in (a). Ownership passes either by release and acquire (P3 then P1) or through the verdict (A3), which orders a dead thread's actions before vd, and vd is sb-before P4. The start time is loaded relaxed; P4's success is what proves that it belonged to the claim being replaced. Ruling out an earlier claim's start time uses (b) for earlier claims, hence an induction on mo(state).

Proof. By well-founded induction on the position of c′ in mo(state) (A0).

  1. Shape (a). After init every state write is a CAS (F7 and participant.rs:201-241). A successful CAS reads its expected value and immediately follows that write (RMW). P1 expects FREE; P2 and P5 expect their own claim's INITIALIZING word; P3 expects its own REGISTERED word; P4 expects the word its P0 loaded, which is never FREE (steal() returns Free first, participant.rs:282). By A4 each value INITIALIZING(c) and REGISTERED(c) is written once in the slot, by c and by its register. So after INITIALIZING(c) comes c's register or a P4 stealing c; after REGISTERED(c) comes c's P3 or a P4 stealing c; after FREE only a P1. A block may be the last one, so each part is "at most".
  2. (c) follows from (a): the write right after c's register, if any, ends c.
  3. (b) for consecutive claims. Let c′ be the next claim after c, and E the ender of c.
    • E is c's P3, and c′ a P1 reading FREE from it. By A2 every action of c is sb-before P3. P3 is a release CAS and P1 an acquire CAS that reads it: P3 sw P1 (REL-ACQ).
    • E=c′, a P4 stealing INITIALIZING(c). The verdict was is_live(pid_c) = Ok(false) (F7). The opening P0 read c before the verdict, identifying an already existing incarnation. By A3 with st=0, every action of c's thread, which has pid_c, happens before vdsb P4.
    • E=c′, a P4 stealing REGISTERED(c). The verdict was is_live_since(pid_c, st), with st loaded at T0. We show that T0 read c's own start-time store Tc (T1 or T2). The register CAS reads c, and P0 reads that register before the verdict, so the incarnation was already observed. Then A3 applies as above (or with st=0).
      • P0 read the write that P4 replaced (A4), which is c's register g, a release CAS. Tcsbgsw P0 sb T0, so T0 reads Tc or a later store (COH-WR).
      • Not an earlier claim's store, nor init's. For a claim c0 before c, the induction hypothesis gives Tc0hbcsbTc, so Tc0moTc (COH-WW); init precedes everything (A1).
      • Not a later claim's store. Every state write after c′ is an RMW, so it lies in rs(c′), and c′ is a release. A later claim c′′ either is a P1, an acquire reading a write in rs(c′), or is a P4 whose own P0 is an acquire reading such a write. Either way c′sw an event sb-before Tc′′, so T0 sbc′hbTc′′, and T0 reads a write mo-before Tc′′ (COH-RW). The stealer's own T2 is sb-after T0 (COH-RW again).
  4. (b) in general. The claiming CAS of a claim is an action on its behalf, and every action of c′ is sb-after its claim (A2). Transitivity along the consecutive claims between c and c′ gives (b).

A reaper that dies between P4 and P6 leaves an ordinary claim of its own, which the next reaper steals under the same rules: the chain of claims in (a) covers it.

OW1. Takeover handoff

Statement. Let a successful O3 o3 by thread θ read the acquiring CAS At of tenure t, held by registration G. Then every action on behalf of G (so everything under t) happens before o3. Consequently t has no O4.

Outline. O3 is a Release CAS: the taker does not synchronise through the owner word. It synchronises through G's slot instead. O1's acquire load of an owner word naming G imports G's register, so the steal's first acquire load P0 sees REGISTERED(G) or a later state. Then either θ steals G itself after a dead verdict, and SL1 gives the order, or it reads a later state. That later state lies in the release sequence of the write that ended G: G's P3, after all of G's actions, or a reaper's P4, after G's death. Without this handoff, an O3 ordered before the owner's O4 in mo would let a second rotator acquire ownership; and the new owner, which builds on the dead owner's R1 and R5, would not see them.

Proof.

  1. θ read the owner word value ω = (slot_G, id_G) at O1 (acquire, rotation.rs:304), and O3 expects ω (rotation.rs:333-335). O1 read some acquiring CAS A′ writing ω. By A4, ω names one registration, G; but A′ may be At or an earlier tenure of G (owner-word ABA: G released and reacquired), so the evidence is about G, not about t. A′ is made by G's thread, after G's register g (only a registered participant rotates; registration_id() asserts it, participant.rs:359-364). A′ is a release (O2 is AcqRel, O3 Release), so gsbA′sw O1 sb P0, and P0 reads g or a later state (COH-WR).
  2. Outcomes of reap_owner() (F6):
    • Live: no O3 follows.
    • Stolen: P0 read g (the only write with id_G at or after g whose kind is REGISTERED), and θ's P4 succeeded, stealing G. SL1(b): every action of G happens before that P4, which is sb-before o3.
    • Free, Other: P0 read a write w≠g, mo-after g. Lost: P0 read g and P4 failed; a failed CAS reads a value other than its expected one, and COH-RR (P0 sb P4) puts that write w after g; P4's failure ordering is acquire. In all three cases an acquire read q of a write w mo-after g, with qsbo3. By SL1(c), w is at or after the ender E of G. All state writes after E are RMWs, so w lies in rs(E), and E is a release: Eswq. If E is G's P3, every action of G is sb-before it (A2). If E is a reaper's P4, SL1(b) orders every action of G before it.
  3. No O4. An O4 of t would be under t, so O4 hbo3, hence O4 moo3 (COH-WW). But o3 immediately follows At (RMW), and O4 is mo-after At (COH-WW, Atsb O4): O4 would lie between them. Contradiction.

In the code the P3 case cannot precede a successful O3: rotate() always runs O4 before returning (rotation.rs:79), so O4 sb P3, and step 3 makes O3 fail. The proof does not need this. Nor does it use any acquire on O3: the taker's edges come from O1, from reap_owner()'s acquire reads and from A3. O3's release serves the next taker's O1 (step 1 for a later takeover).

OW2. Ownership is a lock under hb

Statement.

  • (a) mo(rotation_owner) is init followed by blocks, each an acquiring CAS (O2 or O3), optionally followed immediately by the same tenure's O4. An O2 reads init or the O4 closing the previous block; an O3 reads the acquiring CAS just before it.
  • (b) For tenures t before t′ (by mo of their acquiring CASes), every action under t happens before At′, and before every action under t′.
  • (c) Tenures are totally ordered.

Outline. Once we know that an O4 always sits right after its own tenure's acquiring CAS, every block looks like a lock acquisition and release. The normal handoff is O4's release read by O2's acquire; the takeover handoff is OW1. O3 needs no acquire: it reads an acquiring CAS, and OW1 supplies the order.

Proof.

  1. The writes are init (NONE), O2 CAS(NONE -> me) (AcqRel), O3 CAS(ω -> me) (Release) and O4 store(NONE) (release), one O4 per tenure, sb-after its acquiring CAS.
  2. Adjacency: if O4t exists, it immediately follows At. By induction on the position of At (A0). Let X1 be the write right after At, and suppose X1≠ O4t. If X1 is a CAS, it read At's non-NONE value (RMW), so it is an O3, and OW1 says t has no O4. If X1 is the O4 of another tenure t0, then At0 is before At (At0sb O4t0, COH-WW), and by the induction hypothesis O4t0 immediately follows At0, not At: contradiction.
  3. (a). By step 2 and RMW, an O2 reads NONE from init or from an O4, which closes the previous block; an O3 reads a non-NONE value, which is an acquiring CAS, immediately before it.
  4. (b) for consecutive tenures. If At′ is an O2, it read O4t: every action under t is sb-before O4t (release), and O2 acquires, so O4t swAt′. If At′ is an O3, it read At, and OW1 applies. Actions under t′ are sb-after At′. Transitivity extends (b) to any t before t′; (c) is the totality of mo.

O2 must acquire exactly when it reads an O4; O2 and O3 must release (for O1 in OW1 step 1); O4 must release.

9. Proofs: epochs and seals

EP1. Epoch sequence

Statement. The writes to global_epoch are init (abstracted as one write of 2, A1) and R5s; an R5 of tenure t writes R0(t)+1. Along mo the values are 2, 3, 4, ..., each exactly once. If t precedes t′ and t has an R5, then R0(t′)≥ R0(t)+1; hence R0(t)< R0(t′) implies that t precedes t′. Every thread's successive loads of the epoch are non-decreasing.

Outline. R0 and R5 run only under ownership, so OW2 makes them serial; each R0 then reads the latest earlier R5, and each R5 adds one.

Proof.

  1. Epoch writes: init (the store of 0 at cache/mod.rs:216 and of 2 at 254, one write by A1) and R5 (rotation.rs:196), which writes e+1 after R0 read e (rotation.rs:90) (F5). R0 and R5 are under ownership, at most one each per tenure.
  2. By OW2(b) every R5 of a tenure before t′ happens before R0(t′), and R0(t′) happens before every R5 of a later tenure and its own R5. With init first (A1), the serial-reads lemma says that R0(t′) reads the mo-latest epoch write of an earlier tenure, or init. So each R5 writes one more than the mo-latest epoch write before it: the values along mo are 2, 3, 4, ..., each once (no gaps).
  3. If t precedes t′, R0(t)hb R0(t′) (OW2(b)), so R0(t′) reads the write R0(t) read or a later one (COH-RR), and if t has an R5, R0(t′)≥ R0(t)+1 (step 2). The contrapositive, with OW2(c), gives "R0(t)< R0(t′) implies t before t′".
  4. COH-RR and step 2 make each thread's loads non-decreasing.

EP2. Seal persistence

Statement. For stamp e (arena emod3):

  • (i) Every R4 writing stamp e is made by a tenure with R0 =e−1. There may be several, when an owner dies between R4 and R5 and its taker resets again. All of them precede every tenure with R0 ≥e.
  • (ii) Once Z(e) exists, every ctl write mo-after Z(e) with stamp e is sealed, and every sealed value with a non-zero stamp e is Z(e) itself or mo-after Z(e), on the same word; so Z(e) is unique. It is made by a tenure with R0 =e.
  • (iii) Hence a ctl load returning (stampe,unsealed) reads a write mo-before Z(e): it is cob-before Z(e).

No exact shape of mo(ctl) is claimed: a taker may repeat R4, and after a death between R4 and R5 the only unsealed arena is e+1 while the epoch is still e.

Outline. Only R4 changes a ctl word's stamp. B1 adds a multiple of 2^33 (a carry out of bit 63 is discarded, so bits 0-32 never change), and R1 sets the sealed bit keeping stamp and bump. So after the seal of stamp e, the stamp-e values form an RMW chain that keeps the bit, until an R4 writes another stamp. An R4 stamping e again would need a tenure with R0 =e−1 after the sealing tenure (R0 =e), which EP1 rules out.

Proof.

  1. ctl writes (F5): init (stamp 2 unsealed, or stamp 0 sealed); B1 (keeps stamp and sealed bit); R1 (sets sealed, keeps stamp and bump); R4 of a tenure t (writes (R0(t)+1,unsealed,0) into arena (R0(t)+1)mod3). Stamps are read as full epochs within an operation (A4).
  2. (i). An R4 stamping e is by a tenure with R0 =e−1 (step 1). For any tenure t′ with R0(t′)≥e>e−1, EP1 puts the R4's tenure before t′.
  3. (ii). Z(e) is made by a tenure tZ with R0 =e (R1 seals only a word of stamp R0, rotation.rs:98, 115-120). By (i) and OW2(b), every R4 stamping e happens before Z(e), so it precedes Z(e) in mo (COH-WW); so does init (A1). Walk along mo from Z(e): each later write with stamp e is a B1 or an R1, an RMW reading its immediate predecessor; the stamp of the predecessor is then e as well, so by induction it descends from Z(e) through writes that keep the bit. Each step of that walk goes back along mo (RMW), so the value is Z(e) or mo-after it (transitivity); EP3(ii) needs this order. Likewise every sealed value with a non-zero stamp is a successful R1 or mo-after one, on the same word and with the same stamp (the sealed init values have stamp 0; R4 writes unsealed). Two successful R1s on stamp e are impossible: the later one in mo would read a sealed value, but a successful R1 reads the unsealed value it expects.
  4. (iii). A load returning (stampe,unsealed) reads a write x that is neither Z(e) nor after it (it would be sealed), so x is before Z(e) (mo is total): the load is cob-before Z(e).

EP3. Seal before reuse

Statement. Z(e) happens before:

  • (i) the R4 and R5 of every publishing tenure with R0 =e;
  • (ii) the R1F of every tenure t with R0(t)=e that reaches R1F, whether or not t later publishes;
  • (iii) every event under any tenure with R0 =e+2, its R1F included, which is the fence of the reuse scan;
  • (iv) for e≥2, every event sequenced after an acquire load of the epoch that returns e+1; in particular the C2 and C3 of a recheck whose C1 read e+1.

Form (iii), at R1F, is what the reuse scan relies on; forms (ii) and (iv) are what the readiness scans rely on (PN3).

Outline. A tenure leaves the seal loop only after the seal: its own R1, or a sealed word it loaded, which an earlier tenure sealed (OW2). That holds whether or not the tenure publishes, so the fence it runs right after the loop follows the seal. Two publications later, the seal precedes everything the next-but-one tenure does under ownership. A load that acquires e+1 acquires an R5 that followed the seal.

Proof.

  1. (ii). Let t reach R1F, with R0(t)=e. It left the seal loop (rotation.rs:97-124) either on its own successful R1, which is Z(e) and sequenced before R1F, or on a load l under t, the initial load or a failed CAS, returning u=(stampe,sealed), with lsb R1F (F5). In the second case u is Z(e) or mo-after it (EP2(ii)), where Z(e) is made by a tenure tZ with R0 =e. If t preceded tZ, l would happen before Z(e) (OW2(b)) and would read a write mo-before it (COH-RW): a contradiction. If tZ=t, Z(e) is sequenced before R1F. Otherwise tZ precedes t (OW2(c)), and Z(e) happens before everything under t, R1F included (OW2(b)).
  2. (i). A publishing tenure's R4 and R5 are sequenced after its R1F (F5); apply (ii).
  3. (iii). Let t2 have R0(t2)=e+2. By EP1 it read the R5 of a tenure t1 with R0 =e+1, whose R0 read the R5 of a tenure t0 with R0 =e. By (i), Z(e)hb R5(t0). t0 precedes t1 precedes t2 (EP1), so OW2(b) carries this to everything under t2.
  4. (iv). The load returns e+1≥3, not init's value 2, so it read the R5 of a tenure t0 with R0 =e (EP1), a release: R5(t0)sw the load (REL-ACQ). By (i), Z(e)hb R5(t0). Then follow sb.

Form (ii) does not assume publication because a tenure may certify (R3C) and then die before R5. Form (i) stays limited to publishing tenures: QU1 and SP1 cover every R4 directly.

EP4. Reset before use

Statement. The R4 of a publishing tenure happens before every acquire load (W1) that reads the epoch its R5 wrote.

Outline and proof. R4 sb R5 (F5, one R4 per tenure), R5 is a release and W1 an acquire reading it: R4 sb R5 sw W1 (REL-ACQ).

10. Proofs: pins and quiescence

PN1. Pin writes are release-serial

Statement. The non-announce writes to a pin (W2, W7, P6) are release writes, each made on behalf of a claim, and they are serial (hb totally orders them; mo agrees by COH-WW). Every pin write lies in the release sequence of its head, and has the head's pinned epoch. Hence if an acquire load r of the pin reads a non-announce write N or any write mo-after N, then Nhbr.

Outline. W2 and W7 are the registrant's; P6 is a stealer's, made as the new registrant. So SL1 orders them all. R3A is the only other writer, and it is an RMW keeping the pinned epoch, so it never breaks a release sequence.

Proof.

  1. Pin writes: init (UNPINNED, A1), W2 (release store), W7 (release swap), P6 (release store), R3A (relaxed CAS adding ROTATION_WAITING, F5).
  2. W2 and W7 are made by the registrant (A2); P6 by a stealer after its P5, on behalf of the stealing claim. Actions of one claim are sb-ordered (A2), those of different claims hb-ordered (SL1(b)): the non-announce writes are serial.
  3. Head. Walk back along mo from any pin write w: each R3A is an RMW reading its immediate predecessor (RMW), so w lies in the release sequence of the last non-announce write at or before it (or init), with the same pinned epoch.
  4. Let r (acquire) read w, at or after N. The head H of w is N or after it. H is a release, so Hswr (REL-ACQ); if H is init, then N=init and A1 applies. If NmoH, step 2 and COH-WW give NhbH.

W2's release is essential: a scan may read the registrant's next W2, which must carry the previous attempt's record writes.

PN2. Attempt closure

Statement. Let W2 be the pin store of a store attempt w of registration G. Every action of w from W2 to W7 is, or happens before, every non-announce write N to that pin that is mo-after W2.

The next non-announce write after W2 need not be w's W7 or the P6 of G's own reaper: if that reaper dies after its P4, the clearing P6 belongs to the reaper of the reaper.

Outline. If N is G's own, F1 makes the attempt's W7 come first. If N belongs to a later claim, SL1(b) orders all of G before it. An earlier claim cannot write after W2.

Proof. N is made on behalf of a claim cN (PN1).

  • cN=G. W2 and N are sb-ordered (A2), and Nmo-after W2 rules out Nsb W2 (COH-WW). By F1 (exit) the attempt's W7 is N or sb-before it. Every action of w from W2 to W7 is sb-before or at W7.
  • cN before G in mo(state). SL1(b) gives Nhb W2, hence Nmo W2 (COH-WW): impossible.
  • cN after G. SL1(b): every action of G, those of w included, happens before cN's claim, which is sb-before N.

As a corollary, two store attempts in one slot are hb-ordered (att_order).

PN3. Pin visibility

Statement. Let w be a store attempt in slot i for epoch ew: W2 sb W3 sb B0, and B0 read (stampew,unsealed). Let f be a SeqCst fence with Z(ew)hbf, and Sc any load of slot i's pin with fsbSc. Then Sc reads W2 or a write mo-after it.

No ordering is needed on W2, B0 or Sc. The production instances are:

  • (a) f is the R1F of the tenure with R0 =ew+2, and Sc its R3 load of slot i (reuse, QU1; EP3(iii));
  • (b) f is the R1F of a tenure with R0 =ew, and Sc its R3 load of slot i (readiness, RD1; EP3(ii));
  • (c) f is the C2 of a recheck whose C1 read ew+1, and Sc its C3 load of slot i (readiness, RD1; EP3(iv)).

The attempt w ranges over every store attempt, those of a participant that has just rotated included: W3 is the writer side of every pass. The scan side is f, R1F or C2, never a W3.

Outline. Store buffering: two SeqCst fences, one on each side. The writer's B0 saw the arena unsealed, so it is coherence-before the seal, and the seal happens before f: the writer's W3 comes before f in S. A scan missing W2 would put f before the writer's W3. A writer cutting from its chunk does no RMW on ctl, so only these fences relate it to the rotation.

Proof.

  1. B0 read (stampew,unsealed), so B0 cob Z(ew) (EP2(iii)). With W3 sb B0 and Z(ew)hbf, SC-4.4 (X= W3, a= B0, b= Z(ew), Y=f) puts W3 before f in S.
  2. Suppose Sc read a write mo-before W2. Then Sccob W2, and SC-4.4 (X=f, a=Sc, b= W2, Y= W3, using fsbSc and W2 sb W3) puts f before W3: contradiction (psc is acyclic, A0).
  3. mo(pin) is total, so Sc read W2 or a later write.

QU1. Quiescence before reuse

Statement. Let w be a store attempt for ew. For every tenure t with R0(t)≥ew+2 that executes R4, every action of w from W2 to W7 happens before R4(t).

This covers every R4, a repeated one too. If no tenure with R0 ≥ew+2 executes R4, the statement is vacuous.

Outline. The tenure with R0 =ew+2 scans w's slot after its own R1F, which follows Z(ew) (EP3(iii)). So the scan sees W2 or later (PN3). It passes only on a different pinned epoch, so it read a write whose head is a later non-announce write N: w's W7, a later W2, or a reaper's P6. PN2 puts w before N, PN1 puts N before the scan, and the scan is before R4. Later tenures inherit the order through ownership.

Proof.

Case R0(t)=ew+2.

  1. Before R4, t's holder loaded every slot's pin (A7: all participant_capacity slots) with an acquire load Sc after its R1F f, and the final load passed: pinned epoch UNPINNED or at least R0(t)−1=ew+1 (flag masked) (F5; rotation.rs: load 142, pass test 149). After a reap, the loop reloads, so the final load is the one that passed.
  2. EP3(iii) gives Z(ew)hbf, so Sc read W2 or a later write p (PN3(a)).
  3. The head H of p has p's pinned epoch, which passed, so it is not ew; W2 has pin ew, so H≠ W2. W2 is a non-announce write at or before p, hence W2 moH.
  4. PN2: every action a of w from W2 to W7 is H or ahbH. PN1: HhbSc. And Scsb R4(t).

Case R0(t)>ew+2. R0(t) read a value at least ew+3, so by EP1 (no gaps) some tenure t1 published ew+3, with R0(t1)=ew+2; it has an R4 (F5). The first case gives ahb R4(t1). R0(t1)< R0(t), so t1 precedes t (EP1), and R4(t1)hb R4(t) (OW2(b)).

For a writer that died pinned, the only route from its record writes to the reuse is: its writes, the verdict (A3), the reaper's P6 (release), R3's acquire of the cleared pin, R4. The release sequence of W2 does not cover the record writes, which follow W2. W6 lies between W2 and W7, so the counter reset at R4 also follows every count of the previous incarnation; GenMC's chunked_insert_blocks_reuse checks exactly that pair.

QU2. Incarnations are serial blocks

Statement.

  • (a) If attempts w (epoch e) and w′ (epoch e′≥e+3) exist, every action of w from W2 to W7 happens before every action of w′ from W2 to W7. So the writes that different incarnations make to any arena word are ordered in mo by epoch.
  • (b) No load of w between W2 and W7 reads a write of an attempt for an epoch ≥e+3.

Outline. Through the tenure that published e′: QU1 for its R4, then EP4 to w′'s W1. Going through tenures, not through an induction over incarnations, also handles incarnations with no attempts.

Proof.

  1. w′'s W1 read e′ (F2), not init's 2, so it read the R5 of a tenure t′ with R0(t′)=e′−1≥e+2 (EP1).
  2. QU1: every action of w from W2 to W7 happens before R4(t′). EP4: R4(t′)hb W1 of w′, which is sb-before its W2 and later actions. That is (a); COH-WW turns it into mo order.
  3. (b): a load of w happens before any such write (a), so it cannot read it (COH-RW).

11. Proofs: record space

SP1. B1 lands in its incarnation

Statement. Every B1 of a store attempt for E:

  • (a) reads a ctl value with stamp E, and happens after every R4 that stamps E, repeated resets included;
  • (b) lies in mo(ctl) after the base that its B0's value descends from, and before every R4 stamping E+3.

Outline. Every R4 stamping E belongs to a tenure at or before the one that published E, so it happens before the attempt's W1 (EP4, OW2). Every R4 stamping E+3 comes after the attempt (QU1). Between them, only RMWs that keep the stamp touch the word.

Proof.

  1. Every R4 stamping E is by a tenure with R0 =E−1 (EP2(i)). The attempt's W1 read E from the R5 of a publishing tenure tp with R0 =E−1. A tenure with R0 =E−1 cannot come after tp (its R0 would read at least E, EP1), so every such R4 is at or before tp's and happens before R5(tp) (OW2(b)), hence before W1 (REL-ACQ) and B1. By COH-WW it precedes B1 in mo.
  2. B0 read a value u of stamp E, which is at or after every such R4 (COH-WR from step 1) and descends from a base of E (EP2's ctlbase). B0 sb B1, so B1 reads u or a later write.
  3. B1 is between W2 and W7, so it happens before every R4 stamping E+3 (QU1; that tenure has R0 =E+2), and precedes it in mo (COH-WW).
  4. Between u and B1 lie no R4 stamping E (step 2), no R4 stamping E+3 (step 3), and no other R4 on this arena (they stamp E+3k). So all writes there are B1s and R1s, which keep stamp E.

SP2. Bounded bump, one failure per slot

Statement. Within incarnation E:

  • (a) After a failed B1 by a slot, every later B0 of that slot sees the arena sealed, or its bump past capacity, or another stamp, and stops before B1. So each slot fails at most one B1 per incarnation.
  • (b) Along mo(ctl) the bump is exactly the sum of the claims of the B1s so far. It never exceeds capacity+P·C−nmin, where P is the participant capacity, C the largest claim (chunk or maximal record; every record is at most the maximal record, F3) and nmin (16 bytes, an empty key and value) the smallest record. That bound is reachable. So every B1 has bump+claim<231 by A5: no B1 carries out of the bump field.

Outline. A failure leaves the arena sealed or the bump above capacity, and both persist for the rest of the incarnation, so no success follows a failure and the failing slot stops at its next B0. The last success leaves the bump at most capacity−n+C, and at most one failure per slot follows it.

Proof. By induction along mo(ctl) from the base of E (A0), for both parts together: a failure's new bump exceeds capacity only because the bump did not wrap.

  1. Every claim is at most C: a chunk is C or less by definition, and a record claim n is at most max_record_size (F3).

  2. By SP1, B1 reads a value of stamp E. It succeeds iff that value is unsealed with bump+n≤capacity (store.rs:332); otherwise it fails, leaving the value sealed, or with bump bump+claim≥bump+n>capacity (no wrap, by the induction hypothesis for (b)).

  3. Later writes in E are B1s (bump never decreases) and R1s (set the seal), so "sealed or bump > capacity" persists to the next R4. No success follows a failure.

  4. (a). A later attempt of the same slot happens after the failed B1 (att_order, from PN2), so its B0 reads that B1 or a later write (COH-WR). Seeing another stamp, or sealed, it stops before H1 and B1; seeing bump>capacity, it may still cut from its chunk at H1, but stops at store.rs:311-313, before B1.

  5. (b). The base has bump 0; R1 keeps the bump (seal_bump); B1 adds its claim, so the bump is the sum of the claims. A success needs bump+n≤capacity and adds at most C; let the last success, by slot X, leave the bump at most capacity−n+C. Every failure comes after it, at most one per slot (a).

    • If X does not fail afterwards, at most P−1 failures follow: the bump stays at most capacity+P·C−n.
    • If X fails afterwards with claim c, the B0 of that attempt happens after X's success and found room for c, so the success left the bump at most capacity−c: the bump stays at most capacity+(P−1)·C.

    Either way it stays at most capacity+P·C−nmin. A5 checks capacity+P·C<231 (omitting the nmin slack, config.rs:241-256), so every B1 has bump+claim<231.

A failed B1's bytes are lost (an unindexed hole beyond capacity or in a sealed arena); nothing rolls them back.

SP3. Chunk words are sequential

Statement. Every H1 load of chunk_epoch, chunk_cursor or chunk_end reads the latest store to that word by its own registration. The epoch and end loads read the H2 stores of the chunk's claim; the cursor load reads that H2's store or the last H1 cut since. The cursor stays within [bump + n_0, min(bump + claim, capacity)], where bump, n0 and claim are those of the claiming B1. Only the chunk_epoch reset (H0) before a registration's first W2 is needed, so a chunk left by an earlier registration, or in a stolen slot, is never used.

Outline. The chunk words are touched only by the slot's current registrant, so SL1 makes them sequential. H0 runs before the first pin of every registration and stores epoch 0, which no epoch equals, so a matching chunk_epoch can only come from this registration's own H2. The epoch stored is the full 64-bit epoch: no stamp aliasing.

Proof.

  1. The chunk words are written only by init, H0, H1 (cursor) and H2 (F4), all by the slot's current registrant (in claim() and steal() after the claim; in attempts), and loaded only by H1. By SL1 and A2 they are serial, and every H1 load is hb-ordered against every store: it reads the latest one before it (serial-reads lemma).
  2. The latest chunk_epoch store before an H1 of registration G is G's H0 (value 0, which differs from any e≥2) or an H2 of G in an earlier attempt (F4: G's H0 precedes its first W2). If H1 found chunk_epoch == e, it is an H2 of an earlier attempt w0 of G for the same epoch e (att_order orders the attempts). chunk_end's latest store is the same H2: any later H0 or H2 would also be the latest chunk_epoch store.
  3. The cursor's latest store is that H2's (bump+n0) or an H1 cut since (each advancing by its own n after a room check). The room check end−cursor≥n in u32 is exact, because cursor≤end≤capacity<231 (A5), so cursor+n≤end.

SP4. Disjoint, in-area reservations

Statement. In incarnation E the byte ranges of successful reservations, whether won at B1 or cut from a chunk at H1, are pairwise disjoint and lie in [0, record_area_size). The u32 room check of H1 is exact.

Outline. Successful B1s are RMWs on a bump that never wraps, so their claims [bump,bump+claim) are disjoint intervals. A record takes the first n bytes of its claim; a chunk is the rest, clipped to capacity, and is cut by one registration with an advancing cursor.

Proof.

  1. Successful B1s on ctl of E read their immediate predecessors (RMW) and the bump is exactly the claims so far, with no wrap (SP2): the claims [bump,bump+claim) are pairwise disjoint.
  2. A B1 reservation is [bump,bump+n) with bump+n≤capacity (the success check).
  3. A cut is [cursor,cursor+n) inside [bump + n_0, min(bump + claim, capacity)) of the B1 claim that made the chunk (SP3), so inside that claim, after its own record, and below capacity.
  4. Two cuts of one chunk are disjoint because the cursor only advances (SP3); cuts of different chunks, and a cut against a B1 reservation, lie in different claims (step 1).

SP5. Write-once records

Statement. Each record word is written at most once per incarnation, by the attempt that reserved it (W4 or W5). In the mo of a record word, the writes of different incarnations appear in epoch order.

Outline and proof. An attempt stores each word of its reservation once, inside its reservation (F3); reservations of one incarnation are disjoint (SP4). Across incarnations, QU2(a) orders the writes.

12. Proofs: index and hits

IX1. Publication follows the record

Statement (code-level). Only init (zero fill: stamp 0, offset 0) and I2 write index slots. An I2 of attempt w lies in an index slot of w's arena and writes an entry whose stamp is ewmod232 and whose offset is w's own reservation offset, a multiple of 8. Every word of w's record, the lengths word holding w's lengths included, is stored by w sb-before the I2.

Outline. A writer stores its whole record, then publishes an entry naming it; nothing else writes the index. There is no concurrency argument: this restates F3 and F8 as the one index fact that hit integrity needs. The shape of the index (one slot per key, no gap) is not needed for G1-G3; it is RB4, which G4 needs.

HT1. Recycled reads are caught

Statement. Let a lookup make an arena load Y (index or record word) sb D6 that reads a store of an attempt x for epoch ex. Then V2, sb-after D6, reads an epoch ≥ex. With A6, if ex≥E+3 for a probe of epoch E, V2's u32 age exceeds 1 and the probe returns Retry.

Outline. This is the seqlock-style validation. The writer's W3 is a release fence before its store; D6 is an acquire fence after the load that read the store. So the writer's W1 happens before V2, which therefore sees at least the writer's epoch.

Proof.

  1. x's store is after its W3, and W1x sb W3x (F2, F12). Y reads it and Ysb D6; W3 is a release fence and D6 an acquire fence: W3x sw D6 (FENCE-FENCE). So W1x hb V2.
  2. Both load the epoch: V2 reads W1x's write or a later one (COH-RR), whose value is at least ex (EP1).
  3. A6 keeps V2 below E+232. With ex≥E+3, age_of(V2, E as u32) = V2 - E >= 3 > 1 (util.rs:42-44, probe.rs:200): Retry.

HT2. Hit integrity

Statement. If probe() returns Ok for key k at epoch E (E is V1's e or e−1), then: the entry its I1 read was published by an attempt w with ew=E; V2 read an epoch in [E,E+1]; and every record load of the hit (D4, the lengths, key words and value words D5) read a store of w. So the output is exactly the value w wrote for k, and k was re-checked against w's key. No torn, mixed or recycled hit is returned.

Outline. First identify the record: the entry carries E's stamp, so it is a publication of an epoch congruent to E modulo 2^32. A6 rules out the zero fill and anything 2^32 older, and HT1 rules out anything newer than V2, so it is exactly E's. Then each record load reads w's store: I2's release and I1F's acquire order w's stores before the loads; earlier incarnations precede them in mo (QU2), the same incarnation has no other store (SP5), and later incarnations are caught (HT1). The loads address w's record because each address is computed from values already known to be w's.

Proof.

  1. The entry. I1 read a write x2 whose stamp is Emod232 (F11). By IX1, x2 is the zero fill or an I2 of an attempt w.
    • Zero fill: A6 (entry_life) says an index load after V1 reads an entry of an epoch above V1 −232, the zero fill counting as epoch 0, so V1 <232; then 1≤ V1 −1≤E<232 (V1 is at least 2 by EP1, and E is V1 or V1 −1), so Emod232≠0. Excluded.
    • So x2 is an I2 of w, with ew=E(mod232). A6 gives ew> V1 −232≥E−232. HT1, applied to I1 itself (I1 sb D6), gives V2 ≥ew, and A6 V2 <E+232. So ew=E.
    • V2 passed: age_of(V2, E) <= 1 with E≤ V2 <E+232, so V2 ≤E+1.
  2. Order. w's record stores are sb-before its I2 (IX1), a release write that I1 read; I1 sb I1F, an acquire fence: I2 sw I1F (FENCE-ACQ). So w's record stores happen before every load after I1F.
  3. Each load inside w's record reads w's store. By step 2 it reads w's store or a later one (COH-WR). Writes to that word from other attempts of E do not exist (SP5); those of earlier incarnations precede w's in mo (QU2(a)); one of an attempt with epoch ≥E+3 would make V2 return Retry (HT1). F12 leaves no other writer.
  4. Each load is inside w's record (F11), in program order. D4 is at the entry's offset, which is w's (IX1), so by step 3 it reads w's header and length len. The lengths word at offset + 8 is in w's record and holds w's lengths. The check 8 + align8(key_len) + value_len == len (probe.rs:173) then places the key words and the padded value words inside [offset, offset + 8 + align8(len)), which is w's reservation (F3). Each of them reads w's store by step 3.
  5. The key loads compare w's key with k (probe.rs:176-183), and the value words copied are w's, padding included.

The order of step 4 matters: a recycled word can hold any bit pattern, including a plausible header with stamp E, so D4's stamp check proves nothing by itself, and no safety proof uses record-header stamps. V2 is the defence, and it covers D4 because D4 is itself one of HT1's loads.

HT3. Value provenance

Statement. Every store attempt stores a key and a value that some caller passed together to insert(). So every record published by an I2 pairs its key with such a value.

Outline. An insert stores its caller's pair. A promotion stores its caller's key and the value words of a hit in the previous epoch, which by HT2 are those of an attempt one epoch older with the same key. Induct on the attempt's epoch, which is well-founded. The promoted copy may be the reprobe's hit: that is still a validated hit of e−1, sequenced after V1 and after a miss in e, so HT2 and the induction apply unchanged. HT3 needs no readiness.

Proof. By induction on ew.

  • An insert attempt stores the caller's key and value (F10).
  • A promotion attempt w pinned V1's epoch e (only_epoch, F10) and stores the caller's key k and the value words that the promoted hit for k in epoch e−1 (the first probe of e−1, or the reprobe) copied (F10). By HT2, those words and the matched key are those of an attempt w0 with e_{w_0} = e - 1 < e_w. By the induction hypothesis, w0's pair was passed to some insert(); k equals w0's key, and the value words are w0's, copied whole.
  • An I2 of w publishes w's key (F8, F10).

13. Proofs: bounds, robustness and recency

BD1. Stores stay in the mapping

Statement. Every shared store addresses a word inside the mapping: record stores (W4, W5) lie in the attempt's reservation, hence in the record area; index stores address slot & bucket_mask; slot and arena words use indices below participant_capacity and 3.

Outline. A record store lands in the attempt's own reservation, which lies in the record area; every other store uses a masked or bounded index.

Proof. Record stores: F3 (the stores lie in the reservation, whose size n is exact because payload_size() does not wrap, and at most max_record_size) and SP4. Index stores: put.rs:59. Slots: every slot index is below participant_capacity (loops at cache/mod.rs:231, 269, 295, rotation.rs:133, and the C3 loop, promotion.rs:60; the owner's slot is checked at rotation.rs:232), and arena_of takes epoch % 3 (cache/mod.rs:359-361). These indices address the mapping only under A7.

BD2. Loads stay in the mapping, whatever they read

Statement. Every shared load addresses a word inside the mapping, regardless of the values earlier loads returned:

  • index loads are masked, or lie within a full group of 8: find_candidate::<false> (probe.rs:112-113) is used only when the whole group fits, which relies on the bucket count being a power-of-two multiple of 8 (A5, config.rs:81);
  • every index value, stale ones included, encodes an offset with offset + 16 <= record_area_size, so D4 and the lengths word are in bounds;
  • readers accept a header only if 8≤len≤ras−offset−8 (the u32 bound is exact) and 8 + align8(key_len) + value_len == len, before any key or value load;
  • the output copy stays below align8(value_len) <= align8(output capacity).

C0 loads a word of the arena's first line, in bounds like ctl.

Outline. Nothing a reader loads is trusted until checked, and the one value it uses unchecked, the index entry's offset, is in range for every entry ever written, whatever its incarnation.

Proof.

  1. Index values: zero fill (offset 0) or an I2, whose offset is a reservation's (IX1), so offset+n≤ras with n≥16 (SP4; every record has a header and a lengths word). ras≥16 (A5).
  2. The header check (probe.rs:165-169, put.rs:129-134) computes ras−offset in u32; since offset+8≤ras<231, it is exact. As ras−offset−8 is a multiple of 8, it also bounds align8(len).
  3. The lengths check (probe.rs:173, put.rs:142) is done in 64-bit arithmetic and makes every key and value word lie in [offset + 16, offset + 8 + align8(len)).
  4. The value copy runs while pos < value_len <= output_capacity (probe.rs:186-196); output holds align8(output_capacity) bytes (caller contract, lookup.rs:37-39, 55).

RB1. Live registrant never displaced

Statement. A P4 never replaces a claim whose thread incarnation is still running.

Outline. A steal needs a dead verdict, and A9 rules one out for a running thread.

Proof. P4 follows a verdict Ok(false) about the claim's pid (and start time, SL1 step 3). By A9, a running thread is never reported dead. Not needed for any guarantee: SL1 holds for every steal.

RB2. Live owner never taken over

Statement. An O3 never ends a tenure whose holder is still running.

Outline. A takeover needs evidence that the owner's registration ended, and a running owner ends its registration only after releasing ownership.

Proof. OW1's outcomes Stolen, Free, Other and Lost all show the owner's registration ended (by a dead verdict, A9, or by a write after its ender). A registration ends while its thread runs only by its own P3, after its O4 (rotate() always runs O4 before returning, rotation.rs:79; the remark after the OW1 proof), and then the O3 fails. Not needed for safety: OW1 holds for every takeover.

RB3. Key-check exactness

Statement. In table_put of an attempt w for E, if I0 (acquire) returns an entry with w's stamp, that entry was published by an attempt w′ of E, and every D4 and D5 load of entry_has_key() reads w′'s store, so the check decides on w′'s key.

Outline. The writer's own pin plays the role of the reader's V2: no later incarnation can write while it is pinned.

Proof. As HT2 steps 1-4, with I0's acquire in place of I1F, with w's pin (QU2(b)) in place of V2, and with A6 (entry_life) for the stamp. G1-G3 do not need it: probe() re-checks every hit's key. G4 does, through RB4: without it a key could get a second slot in one incarnation, and the mo-last write in the hit's slot would not be the last publication of the key. It needs I0's acquire.

RB4. Index shape

Statement. Within incarnation E:

  • (a) all publications of E in one slot carry the same key;
  • (b) a key's publications of E are in one slot;
  • (c) every slot from the key's home to that slot holds a publication of E for another key that happens before each publication of the key;
  • (d) a CAS publication of E in a slot is mo-before every other publication of E in that slot. A promotion publishes only by CAS (F9), so once an entry of E is in place, every later publication of E in that slot is an insert's I2 store.

Outline. Within an incarnation an index slot, once taken, keeps its key, and a writer moves past a slot only when it holds another key. (d): a CAS replaces only an entry without its stamp; it read its immediate mo-predecessor, and any publication of E at or before that predecessor would carry the stamp.

Proof. (a)-(c): a CAS replaces only an entry without its stamp (F8), a store only an entry for its key (F9, RB3), and no other incarnation's write falls inside E's block (QU2(a), A6). So once a slot holds an entry of E, it keeps that key (induction on mo, A0). A writer advances past a slot only after finding there an entry of E for another key (F9; a failed CAS re-reads the same slot, put.rs:93-97); its I0 acquired that entry, so the entry happens before the writer's I2. With equal keys having equal hashes (A8) and each slot visited once (dist_inj), the key cannot also sit further on.

(d):

  1. Let x be a CAS by an attempt of E in slot l, and y a publication of E in l with ymox.
  2. x read its immediate mo-predecessor r (RMW), so y=r or ymor.
  3. r is the zero fill or an I2 (F8). The zero fill is impossible: y would be at or before init (A1). An I2 of an attempt of E carries the stamp of E (F8), but the CAS expects an entry without it (F8). An I2 of an attempt for an epoch ≥E+3 is impossible: x is mo-after it, against QU2(a). For an epoch ≤E−3, rmoy (QU2(a)), against y at or before r. No other epoch writes that arena (F12).
  4. The second sentence follows from F9: a promotion never stores.

(d) is the CAS branch of the argument for (a), made explicit. G1-G3 do not need RB4. G4 needs (a), (b) and (d) for FR2 and FR3, and (c) for FR3's case E=φ−1 and for FR4.

RB5. Pins balanced on return

Statement. Every return of insert() and lookup() leaves the caller's slot unpinned, errors, dropped promotions and FullRejected included; rotate() and release_claim() are entered unpinned.

Outline. Every path out of reserve() and store() after a W2 runs a W7 first.

Proof. By reading (F1): reserve() unpins (W7, store.rs:352) before every non-reservation exit after W2 (store.rs:353-359), and returns before W2 when the promotion's epoch moved (store.rs:269-271); store() unpins (store.rs:175) right after publication, before any rotate() or return. lookup() pins only through store(). A leaked pin would only stall reuse until R3 times out or reaps the slot. production_asserts check the entry conditions (rotation.rs:76, participant.rs:238, lock.rs:144-149).

Recency. The remaining invariants carry G4. They add no axiom to A0: only REL-ACQ, release sequences of RMWs, FENCE-ACQ, SC-4.4 and the coherence rules. RD1 is QU1's core argument with "pinned epoch ≠n" in place of "passes"; RD2 is a release-sequence argument over fetch_max; FR1-FR4 combine them with HT2 and RB4. No proof uses the sampler, fairness, or readiness ever being reached.

RD1. Certificate soundness

Statement. Let c be a certificate Cert(n): an R3C of a tenure with R0 =n, or a C4 of a recheck whose C1 read n+1. Then every action from W2 to W7 of every store attempt for n happens before c.

A store attempt is, by definition, a pass whose B0 saw its incarnation unsealed (section 3.2). A pass for n whose W3 follows the certifier's fence in S sees the seal at B0, so it is not an attempt and publishes nothing in n. The certifier neither waits nor reaps.

Outline. The certifier fences after the seal of n (EP3(ii) or (iv)). It then loads every slot's pin with acquire and finds none pinned to n. By PN3, each load read the attempt's W2 or a later write. A value with a different pinned epoch has a later non-announce head: an unpin, a new pin or a reaper's clear. PN2 orders the attempt before that head, PN1 orders the head before the load, and the load is sequenced before c. This is QU1's argument with "pinned epoch ≠n" in place of "passes".

Proof.

  1. Let f be the certifier's fence: the tenure's R1F (rotation case) or the recheck's C2 (recheck case). EP3(ii) or EP3(iv) gives Z(n)hbf. In the recheck case, if n+1=2 then n=1, and no attempt has epoch 1 (every W1 reads at least 2, EP1), so the statement is vacuous.
  2. Let w be an attempt for n in slot i. By A7, the certifier loads slot i at least once after f and before c (F5, F13). In the rotation case every R3 load of slot i is tested for pinned epoch n (rotation.rs:144-148), and R3C runs only if none matched: take any of them. In the recheck case take the C3 load of slot i. That load Sc is acquire and returned a pinned epoch other than n.
  3. PN3, instance (b) or (c): Sc read W2 or a write p mo-after it.
  4. The head H of p has p's pinned epoch (PN1), which is not n. W2's is n, so H≠ W2. W2 is a non-announce write at or before p, so W2 moH, and H is not init.
  5. PN2: every action a of w from W2 to W7 is H or ahbH. PN1: HhbSc. And Scsbc.

The recheck's own ordering is redundant on the reachable path. A recheck runs only after a validated hit of n in the same pass. Its V1 read n+1, which only the R5 of a tenure t with R0 =n writes, and V1 is sequenced before the hit's I1F, so that R5 synchronises with I1F (FENCE-ACQ). t ran its R1F-fenced scan before its R5 (F5), and by PN3(b) each of its R3 loads of slot i read W2 or later. C3 happens after that load, so it reads at or after what the load read (COH-RR). So C3 sees what t's scan saw or later, without C1's acquire or C2. GenMC agrees: relaxing C1, removing C2, and both together, all pass. The proof above keeps the local argument, which does not depend on the hit that precedes the recheck.

RD2. Certificate visibility

Statement. Let r be an acquire load (C0) of the readiness word of arena nmod3 that returns n, with n≥1. Then some certificate c for n (a fetch_max with argument n) synchronises with r. With RD1, every action of every store attempt for n happens before r.

Outline. The word is written only by init (value 0) and by certificates, which are release fetch_max RMWs (F13). The mo-first write with value n must be a fetch_max with argument n. Every later write up to the one r read is an RMW, so all of them are in its release sequence. A delayed certificate with a smaller argument neither lowers the value nor breaks the sequence. The value is the full 64-bit epoch, compared exactly, and is never reset (R4 does not write it), so a certificate for n−3k on the same word, or for an epoch that matches n in its low 32 bits, is never mistaken for one for n.

Proof.

  1. r read a write z whose value is n≠0, so z is not init (F13).
  2. By well-founded induction on mo (A0), z lies in rs(c) for a certificate c with argument n. z is a certificate c′ that writes the maximum of the value it read and its argument (F13). If its argument is n, take c=c′. Otherwise its argument is smaller and the value it read is n: c′ read its immediate predecessor y (RMW), whose value is n. The induction hypothesis gives a c with y in rs(c), and c′, an RMW that reads y, extends rs(c).
  3. c is a release write and r an acquire load that reads from rs(c): cswr (REL-ACQ).
  4. Compose with RD1.

The init write need not be mo-first: its value 0 suffices. A plain release store in place of fetch_max would break step 2: a delayed store with a smaller argument would lower the value and end the release sequence.

FR1. Fresh source

Statement. Let a lookup with V1 =n+1 promote the hit H of a probe of n (F10). Then every action from W2 to W7 of every store attempt for n happens before the I1 that read H's entry.

Outline. F10 allows only two promoted hits. H is the hit of a probe::<true> whose C0 returned n: RD2 and then RD1 apply, and C0 is sequenced before that probe's I1 loads. Or H is the reprobe's hit, sequenced after a successful recheck: its C4 is a certificate for n (RD1), sequenced before the reprobe's I1 loads.

Proof.

  1. F10: the lookup promotes only on the promotion_ready flag of a probe::<true> hit (set only when C0 read n), or after reprobe_for_promotion() returned a hit, which it does only after the recheck returned true, so after C4.
  2. C0 case. By RD2, every attempt action happens before C0, and C0 is sequenced before the home I1 (probe.rs:74, before line 99), which is the I1 that read H's entry or is sequenced before it.
  3. Reprobe case. By RD1, every attempt action happens before C4, and C4 is sequenced before the reprobe's first I1 (promotion.rs:66, then lookup.rs:198), hence before the one that read H's entry.
  4. Why the placement matters: a certificate learned after an I1 says nothing about what that I1 read, which need not follow the attempts. That is why C0 comes before the first I1, and why the reprobe exists. A stale first copy can be returned, but not promoted.

FR2. Promotion freshness

Statement. Let a promotion attempt w, for n+1 and key k, promote the hit H in n. Then the entry x2 that H's I1 read is a publication of k by an attempt w0 for n, and w stores w0's value (HT2, HT3). Every publication y of k by an attempt for n, insert or promotion, lies in x2's slot, and y=x2 or ymox2. So the promoted record is that of the mo-last publication of k in incarnation n: the last insert store into the key's slot, or the slot's CAS if no insert store followed it (RB4(d)). Nothing is assumed about timing, about sampling, or about readiness ever being reached.

Outline. All of k's publications in n are in one slot (RB4(b)). FR1 makes each of them happen before the I1 that read x2, so by COH-WR that I1 read the last one. HT2 then identifies the record and the value.

Proof.

  1. HT2: x2 is an I2 of an attempt w0 for n; H's record loads read w0's stores, the key check matched k, and the copied words are w0's (F10, HT3).
  2. RB4(b): y lies in x2's slot s.
  3. FR1: y, an action of an attempt for n, happens before H's I1.
  4. COH-WR on s: y=x2 or ymox2.
  5. Limits. If the source arena is being reused, the probe returns Retry or Miss (HT1, F14) and nothing is promoted. The promotion itself may be dropped (only_epoch, a full arena). RB4(c) (no gap) is not needed here.

FR3. Read-after-insert: no resurrection

Statement. Let insert(k, v) =I return Ok. Let L be a lookup of k whose final pass's V1 happens after I's return; in particular, a call that happens after that return qualifies. L may miss. If it returns a hit, every root of the attempt whose record it returns is I, or an insert of k that does not precede I: a later or concurrent insert, never one that returned before I was called. This holds regardless of promotions or rotations, even after I's generation has been evicted. No retention is assumed. The claim is about provenance: two inserts may store equal values.

By F15, an attempt wI of I published before the successful return. Write φ for its epoch, PI for its publication, and s for its slot. In Lean, successful_insert_no_resurrection obtains this publication from InsertOps.ok_pub and applies no_older_value in Recency.lean.

Outline. Let g be what V1 read in L's final pass (g≥φ), and E the epoch of the returned hit (g or g−1). If E=φ, PI happens before the hit's I1, so the hit read PI or a later publication of k in s, and those are stores of inserts that do not precede I (RB4(d)). If E≥φ+1, by induction on E every publication of k in E has such a root: inserts at E do not happen before I's W1, and promotions copy the last publication of E−1 (FR2). If E=φ−1, so g=φ, the probe of φ before it missed; that needs one of its loads to read a write of incarnation φ+3 or later, and the returned hit's D6 then forces Retry.

Proof.

  1. g≥φ. wI's W1 read φ; it is sequenced before I's return, which happens before the final V1. COH-RR and EP1 give g≥φ.
  2. Lemma A. Every publication of k by an attempt for φ lies in s (RB4(b)). One that is mo-after PI is not a CAS (RB4(d)), so it is the I2 store of an insert attempt (F9), of an insert J. J does not precede I: otherwise J's I2 is sequenced before J's return, which happens before I's call, which is sequenced before PI (F15), and COH-WW would put it mo-before PI.
  3. Lemma B. An insert attempt for h≥φ+1 belongs to an insert J that does not precede I. Otherwise its W1 happens before wI's W1 (F15), and COH-RR with EP1 gives h≤φ.
  4. OK(h), for h≥φ+1, by strong induction on h: every publication of k by an attempt for h has a root that does not precede I. Insert attempts: Lemma B (an event belongs to one attempt, F2, and an attempt to one insert, F15). Promotion attempts: their root is that of the attempt that published the copied entry x2, which FR2 makes the mo-last publication of k in h−1. If h−1=φ, PI is such a publication, so x2=PI (root I) or x2 is mo-after it, and Lemma A applies. If h−1>φ, OK(h−1) applies.
  5. Case E≥φ+1. The returned record's entry is a publication of k for E (HT2): OK(E).
  6. Case E=φ. PI is sequenced before I's return, which happens before the final V1, which is sequenced before the hit's I1: PI happens before that I1. HT2 and RB4(b) put the hit's entry x2 in s, and COH-WR gives x2=PI or PImox2. Conclude with Lemma A.
  7. Case E=φ−1, so g=φ and the probe of φ returned Miss. By F14, with d=dist(k,s), a load Y of that probe, the I1 of a slot at distance ≤d or a record load of a candidate there, read something other than its expected value: for a chain slot before s, an entry stamped φ (for another key); for s, the entry stamped φ for k; for a candidate's record loads, the record of the attempt that published the entry its I1 read. Each expected write happens before Y: chain entries by RB4(c), as each happens before PI, which happens before the probe (step 5); s's by step 5; record stores because I2 synchronises with I1F (FENCE-ACQ, as in HT2 step 2). So Y read that write or one mo-after it (COH-WR). The mo-later writes of incarnation φ keep, in an index slot, the stamp and the key (RB4(a)), hence the tag (A8), so they are expected values too; record words are written once per incarnation (SP5). Writes of earlier incarnations are mo-before (QU2(a)), and the epochs φ+1 and φ+2 do not write arena φmod3 (F12). So Y read a store of an attempt for an epoch ≥φ+3. Y is sequenced before the D6 of the returned hit's probe (the probe of φ−1, or the reprobe; F14), so by HT1 that probe's V2 reads at least φ+3>E+1, and it returns Retry (A6), not a hit: a contradiction.
  8. Hence every returned hit has a root as claimed. Nothing uses sampling, fairness, or readiness being reached.

Limits. "Precedes" is happens-before, not real time. Inserts concurrent with I, including later-generation ones, may win. Lookups that do not happen after I may return an older value, but their promotions cannot make a lookup covered by this theorem return a superseded insert's record. An insert that fails with an error other than Corrupt is invisible (FR5), but a lookup after it need not return the previous value.

FR4. Retention: the lookup does not miss

Statement. Take FR3's setting, and suppose that L's final pass read g∈{φ,φ+1} at V1, and that no load of that pass reads a store of an attempt for an epoch ≥φ+3 (retention). Then L does not return Ok(None): it returns a hit (to which FR3 applies), InsufficientCapacity or Corrupt.

Sufficient conditions:

  • L's return happens before the R5 that publishes φ+3. Every write of an incarnation ≥φ+3 is made by an attempt whose acquire W1 read that R5 or a later one (EP1; OW2 orders the later ones after it), so COH-RW keeps L's loads off those writes. This gives retention only.
  • L's return happens before the R5 that publishes φ+2. OW2 orders it before the R5 that publishes φ+3, which gives retention, and by COH-RW V1 reads an epoch below φ+2. This gives both hypotheses.

Without retention the claim is false, because misses are not validated. During a concurrent reuse of arena φmod3, a stale chain slot or a recycled D4 header returns Miss without reaching V2. And for g≥φ+2, L may miss: there may be no copy in φ+1 or φ+2, a promotion may have been dropped or not made, or I may have landed in φ when the epoch was already φ+2.

Outline. The probe of φ reads, along k's chain, entries of φ for other keys that happen before PI (RB4(c)), then PI or a later entry for k at s, and the records of those entries. It is the probe of the current arena if g=φ; if g=φ+1 and the probe of φ+1 missed, it is the probe of the previous arena, or the reprobe. Retention excludes later incarnations, so F14's condition for a miss cannot arise.

Proof.

  1. The probes of φ in the final pass: if g=φ, the probe of the current arena. If g=φ+1 and the probe of φ+1 returned a hit or InsufficientCapacity, there is nothing to show. Otherwise it missed, and the probes of φ are the probe of the previous arena and possibly the reprobe.
  2. For each such probe, apply step 6 of FR3, but conclude directly: a Miss needs a load at distance ≤dist(k,s) that read a store of an attempt for an epoch ≥φ+3 (F14), which retention excludes. So that probe does not return Miss.
  3. Retry is not an outcome of the final pass, by definition. The remaining outcomes are a hit, InsufficientCapacity and Corrupt.

FR5. Failed inserts are invisible

Statement. Let the insert J return an error other than Corrupt. No store attempt that descends from J makes an I2. So no index entry is a publication by such an attempt, and no lookup returns a hit whose record such an attempt wrote: neither J's value directly nor a promoted copy of it, in any generation. Corrupt returns are outside this guarantee.

Limits. A failed insert can still have side effects: the rotations it performs or triggers, which evict the oldest generation, so an older value of the key may stop being returned; slot reaping; and record-area space consumed by bytes reserved, or written but never indexed. So it is not guaranteed that a lookup after a failed insert returns the previous value; it is guaranteed only that it does not return the failed insert's value, nor a copy of it. GenMC's promotion_keeps_newer_stale_epoch_insert checks the instance inserted.is_ok() || last == V1, in a configuration where V1 stays retained (it is published in epoch 2 and the run ends at epoch 3).

Outline. An insert that returns an error other than Corrupt made no publication of its own. A promotion descends from J only through a hit, and a hit's entry is a publication (HT2) by an attempt one epoch earlier; by induction on the epoch, nothing that descends from J ever publishes.

Proof.

  1. J's attempts make no I2. Exit (3) of F15 returns Corrupt, so J returned on exit (1) or (2). On those exits, no attempt of J made an I2. Only an attempt that reserve() returned reaches table_put, and each such attempt of J returned FullRejected, which makes no I2 (F15): only FullRejected repeats store()'s loop, exit (2) follows one, and on exit (1) the last reserve() returned no reservation.
  2. No attempt that descends from J makes an I2, by strong induction on the attempt's epoch ew. If w is an attempt of J, step 1. Otherwise w is a promotion attempt whose promoted hit's I1 read an entry x2 published by an attempt w0 that descends from J (section 3.2). The hit is in epoch ew−1 (F10), so by HT2 x2 is an I2 of w0 with ew0=ew−1. The induction hypothesis says w0 makes no I2: a contradiction. So the only attempts that descend from J are J's own, and none of them publishes.
  3. Index entries. Index slots are written only by the zero fill and by I2s, each the publication of its own attempt's record (F8). By step 2, none is a publication by an attempt that descends from J.
  4. Lookups. A lookup returns a hit only when probe() returns Ok. By HT2, the hit's entry is an I2 of an attempt w, and every record load of the hit read a store of w: the returned record is w's. By step 2, w does not descend from J, and, each attempt having exactly one root (section 3.2), its root is another insert. This covers every generation and every chain of promotions.
  5. Nothing uses readiness, sampling, timing, or the epoch in which J's attempts reserved.

16. Gaps and risks

The proofs found no safety violation under A0-A9 and F1-F15.

  1. A3 carries all crash recovery. Every step about a dead participant (SL1 step 3, OW1, QU1's dead writer) reduces to "the dead thread's writes happen before the verdict". On Linux that is /proc/<tid>/stat followed by membarrier(MEMBARRIER_CMD_GLOBAL), which no memory model covers; the GenMC programs replace it with GetPid fixtures. With NoopGetPid nothing is ever reaped.

  2. Recency: promotions cannot hide a completed insert. Without promotion readiness, this trace would let a promotion shadow a newer insert:

    1. insert(k, v2) pins e−1, and the rotation e−1→e happens.
    2. A lookup reads e at V1, misses in e, and hits the older v1 in e−1.
    3. The insert publishes v2 in e−1 and returns.
    4. The promotion publishes v1 in e; later lookups return v1.

    Readiness blocks it. The rotation's scan sees the insert's pin (R3), so the lookup's C0 finds no certificate and the early hit of v1 is returned but not promoted. A certificate obtained later, by a recheck, leads only to a fresh probe, which reads v2 (FR1, FR2). promotion_keeps_newer_stale_epoch_insert checks that a lookup after the successful insert reads v2. What remains: G4 orders by happens-before, not by real time; a lookup concurrent with an insert may return an older value; inserts of one key that are not ordered by happens-before are not ordered at all, including one that lands in a later generation; a failed insert is invisible (G5), but its rotations may evict the key's older value, so a lookup after it need not return the previous value; and a lookup that retries to φ+2 or later, where φ is the epoch in which a successful insert of the key published, may miss (FR4).

  3. Misses are not validated. A probe can return Miss from a stale index word, or from a recycled header at D4, without reaching V2. That is sound for a cache; HT2 speaks of hits only. It is why FR4 needs retention.

  4. A4: id spending and counter wrap. Registration ids come from a u32 counter that wraps (zero skipped). The rotation reapers (reap_pinner(), reap_owner()) draw an id only after a dead verdict (rotation.rs:207, 236). A registration spends one id per register_participant() call, drawn before its scan (cache/mod.rs:268) and used for at most one successful claim or steal (cache/mod.rs:298). So ids are spent per registration call and per dead slot a rotation reaps. SL1 step 3 still needs a claim's word never to recur in its slot while held, which is why a taker never reuses its own id for the slot it steals.

  5. A2 outside the C API. The fork guard (fork_generation) lives in ffi.rs; the C API also forbids use from a signal handler (ffi.rs:139-141). A Rust caller that forks while holding a ParticipantLock, or a signal handler that inserts on the interrupted thread's registration, has two flows of control acting for one registration, which voids SL1 (a handler's W2'/W7' can give a torn hit).

  6. A7 and from_raw. The parameters are not checked against the header. An attacher with a smaller participant_capacity would skip slots in R3, breaking QU1, and in R3's readiness test and C3, certifying readiness falsely and letting a stale copy be promoted (RD1).

  7. Liveness holes. Wake-ups, the wait budgets and the timeouts are not treated. Known holes:

    • A claim that dies while INITIALIZING is identified by its TID alone; while a live thread reuses that TID, the slot cannot be reaped, nor its pin cleared (participant.rs:268-274).
    • A FREE slot whose pin is not UNPINNED would block reuse for good: steal() reports Free and reaps nothing. The code keeps it from arising (P3 asserts an unpinned slot, P6 precedes a stealer's P3), but no invariant states it.

  8. Protocol fidelity is checked by reading. The proofs derive the invariants from F1-F15, not from the Rust source; that the source has F1-F15 is checked by reading, and GenMC checks the source only on small configurations.

  9. Promotion hit rate. A rotation certifies e only if no slot is pinned to e during its scan, which inserts under load often prevent. An unready previous-generation hit is then rechecked with probability min(1, 8 / bucket_count), so roughly bucket_count / 8 such hits may go unpromoted per generation before a recheck succeeds, and a dead or slow pinner of e suppresses promotion from e for as long as e is the previous generation. That degrades the LRU approximation, never safety. Measured with sgc_bench (benches/README.md, 5 interleaved rounds, a 32-vCPU Zen 5 Linux VM), against the same code without readiness: throughput is unchanged within noise in every scenario, through both the Rust and the C API (geomean 1.009 and 1.006), so C0's acquire load does not show; the hit rate is unchanged except in mixed/1Mi/s0.8 with 4 and 8 threads, the scenario with the most inserts (58% of operations), where it drops by 0.25 to 0.4 percentage points (41.8% to 41.6% and 41.4%). Single-threaded runs are unaffected: no other pin is held when the rotation scans.
